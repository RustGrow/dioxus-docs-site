# Интерактивность

Теперь, когда наше приложение *HotDog* собрано и стилизовано, мы можем наконец добавить интерактивные элементы.

## Инкапсуляция состояния

Прежде чем мы углубимся, давайте разделим наше приложение на две части: `Title` и `DogView`. Это поможет нам организовать наше приложение и держать состояние `DogView` отдельно от состояния `Title`.

```rust
#[component]
    fn App() -> Element {
        rsx! {
            document::Stylesheet { href: CSS }
            Title {}
            DogView {}
        }
    }

    #[component]
    fn Title() -> Element {
        rsx! {
            div { id: "title",
                h1 { "HotDog! 🌭" }
            }
        }
    }

    #[component]
    fn DogView() -> Element {
        rsx! {
            div { id: "dogview",
                img { src: "https://images.dog.ceo/breeds/pitbull/dog-3981540_1280.jpg" }
            }
            div { id: "buttons",
                button { id: "skip", "skip" }
                button { id: "save", "save!" }
            }
        }
    }
```

## Обработчики событий

В компоненте `DogView` мы хотим присоединить действие к клику кнопок. Например: пропуск или сохранение текущего фото собаки. Мы можем использовать [EventHandler](../essentials/basics/event-handlers.md) для прослушивания событий `click`.

Обработчики событий похожи на обычные атрибуты, но их имя обычно начинается с `on` — и они принимают замыкания как значения. Замыкание будет вызвано всякий раз, когда его соответствующее событие срабатывает. Слушатель получает информацию о событии из объекта [Event](https://docs.rs/dioxus/latest/dioxus/prelude/struct.Event.html).

Мы добавим несколько замыканий inline и передадим их в атрибут `onclick` для кнопок *skip* и *save*:

```rust
#[component]
    fn DogView() -> Element {
        let skip = move |evt| {};
        let save = move |evt| {};

        rsx! {
...
            div { id: "buttons",
                button { onclick: skip, id: "skip",  "skip" }
                button { onclick: save, id: "save",  "save!" }
            }
        }
    }
```

> Вы можете прочитать больше об обработчиках событий в [справочнике по обработчикам событий](../essentials/basics/event-handlers.md)

## Состояние с use_hook

До сих пор наши компоненты не имели внутреннего состояния. Для нашего `DogView` мы хотим менять отображаемое фото собаки всякий раз, когда пользователь нажимает *skip* или *save*.

Чтобы хранить состояние в компонентах, Dioxus предоставляет функцию `use_hook`. Это позволяет простым функциям Rust хранить и загружать состояние без использования дополнительной структуры.

При вызове в компоненте функция `use_hook` вернет `.clone()` изначально сохраненного значения:

```rust
#[component]
    fn DogView() -> Element {
        let img_src = use_hook(|| "https://images.dog.ceo/breeds/pitbull/dog-3981540_1280.jpg");

..

        rsx! {
            div { id: "dogview",
                img { src: "{img_src}" }
            }
..
        }
    }
```

Хуки Dioxus очень похожи на хуки React и должны следовать некоторым [простым правилам](../essentials/basics/hooks.md) для правильной работы.

## Сигналы и use_signal

Хотя `use_hook` позволяет хранить любое значение, реализующее `Clone`, вы часто будете хотеть более функциональную форму управления состоянием. Встроенные в Dioxus — *сигналы*.

`Signal` — это тип-обертка вокруг обычного Rust-значения, которая отслеживает чтения и записи, оживляя ваше приложение. Вы можете обернуть любое Rust-значение в сигнал. Сигналы можно создавать вручную с помощью `Signal::new()`, но мы настоятельно рекомендуем вместо этого использовать хук `use_signal`.

> 📣 Ручное создание сигналов требует помнить о вызове `.manually_drop()` на сигнале, тогда как `use_signal` автоматически очищает сигнал за вас.

Всякий раз, когда значение сигнала меняется, его содержащаяся «реактивная область" будет «помечена как грязная" и перезапущена. По умолчанию компоненты Dioxus являются реактивными областями, и, таким образом, будут перерисовываться всякий раз, когда меняется значение сигнала.

Сигналы являются основой Dioxus и требуют времени на освоение. Мы рекомендуем внимательно прочитать [руководство по основам](../essentials/basics/index.md), прежде чем погружаться в ваше первое крупное приложение.

## Глобальное состояние с помощью Context

Хотя хуки хороши для состояния *локального* для компонентов, иногда вам захочется управлять состоянием для вашего *всего* приложения. Dioxus предоставляет два механизма: `Context` и `GlobalSignal`.

API `Context` позволяет родительским компонентам совместно использовать состояние с дочерними компонентами без явного объявления дополнительного поля свойства. Это используется более крупными приложениями и библиотеками для совместного использования состояния по всему приложению без изменения сигнатур компонентов.

Чтобы «предоставить" контекст, просто вызовите `use_context_provider()` со структурой, реализующей `Clone`. Чтобы прочитать контекст в дочернем элементе, вызовите `use_context()`.

```rust
// Create a new wrapper type
    #[derive(Clone)]
    struct TitleState(String);

    fn App() -> Element {
// Provide that type as a Context
        use_context_provider(|| TitleState("HotDog".to_string()));
        rsx! {
            Title {}
        }
    }

    fn Title() -> Element {
// Consume that type as a Context
        let title = use_context::<TitleState>();
        rsx! {
            h1 { "{title.0}" }
        }
    }
```

Вы можете комбинировать `use_signal` и `Context` для предоставления реактивного состояния вашему приложению:

```rust
#[derive(Clone, Copy)]
    struct MusicPlayer {
        song: Signal<String>,
    }

    fn use_music_player_provider() {
        let song = use_signal(|| "Drift Away".to_string());
        use_context_provider(|| MusicPlayer { song });
    }
```

С помощью `use_context` и `consume_context` вы можете легко получить доступ к модификации этого состояния:

```rust
#[component]
    fn Player() -> Element {
        rsx! {
            button {
                onclick: move |_| consume_context::<MusicPlayer>().song.set("Vienna".to_string()),
                "Shuffle"
            }
        }
    }
```
