# LiveView

LiveView позволяет приложениям *выполняться* на сервере и *рендериться* в браузере. Он использует WebSockets для коммуникации между сервером и браузером.

Примеры:
- [Простой пример](https://github.com/DioxusLabs/dioxus/tree/main/packages/liveview/examples/axum.rs)

## Поддержка

Dioxus LiveView будет перенесён в [dioxus-fullstack](../../essentials/fullstack/index.md) в будущем релизе. После этого переноса вам может понадобиться обновить свой код. Мы планируем, что этот перенос будет минимальным.

LiveView в настоящее время ограничен по возможностям по сравнению с веб-платформой. Приложения LiveView выполняются на сервере в нативном потоке. Это означает, что браузерные API недоступны, поэтому рендеринг WebGL, Canvas и т.д. не так прост, как в вебе. Однако нативные системные API доступны, поэтому стриминг, WebSockets, файловая система и т.д. — все жизнеспособные API.

## Интеграция с роутером

В настоящее время Dioxus Router не интегрируется с историей браузера в рендерере LiveView. Если вы заинтересованы в добавлении этой функции в Dioxus, эта проблема отслеживается [здесь](https://github.com/DioxusLabs/dioxus/issues/1038).

## Управление задержкой

LiveView делает общение с сервером из клиента невероятно удобным, но есть и некоторые недостатки. Главным образом, в Dioxus LiveView каждое взаимодействие по умолчанию проходит через сервер.

Поэтому при использовании рендерера LiveView вам нужно быть очень внимательным к управлению задержкой. События, которые были бы достаточно быстрыми на других рендерерах, такие как [контролируемые вводы](../../essentials/basics/event-handlers.md), могут быть неприятны в использовании в рендерере LiveView.

Чтобы обойти эту проблему, вы можете внедрять фрагменты JavaScript в ваше приложение LiveView. Если вы используете raw-атрибут в качестве слушателя, вы можете внедрить JavaScript, который будет выполняться при срабатывании события:

```rust
rsx! {
    div {
        input {
            "oninput": "console.log('input changed!')"
        }
    }
}
```
