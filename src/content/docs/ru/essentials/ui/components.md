# Компоненты и свойства

В Dioxus компоненты — это простые функции, инкапсулирующие представление, состояние и взаимодействие вашего интерфейса. По мере роста приложений имеет смысл объединять общую функциональность в более мелкие переиспользуемые компоненты. Модульные компоненты облегчают работу в больших командах, предотвращают раздражающие ошибки и обеспечивают лучшее повторное использование кода на всех платформах.

## Определение компонентов

В простейшем виде компонент — это функция, возвращающая Element. Например, базовый компонент `app`:

```rust
fn app() -> Element {
  rsx! { "hello world!" }
}
```

Если вы хотите использовать компонент из другого компонента, вы должны аннотировать функцию макросом `#[component]`. Этот макрос предоставляет важные метаданные макросу RSX, позволяя аргументам функции становиться полями в свойствах компонента. Ваша функция должна соответствовать следующим требованиям:

- Либо начинаться с заглавной буквы (`MyComponent`), либо содержать подчёркивание (`my_component`)
- Принимать аргументы, реализующие [`PartialEq`](https://doc.rust-lang.org/std/cmp/trait.PartialEq.html) и [`Clone`](https://doc.rust-lang.org/std/clone/trait.Clone.html)
- Возвращать [`Element`](https://docs.rs/dioxus/latest/dioxus/prelude/type.Element.html)

Аргументы, которые принимает компонент, называются его **свойствами (properties)**. Свойства используются для передачи данных в компонент, аналогично тому, как вы передаёте аргументы в функцию.

Например, мы можем определить простой компонент, принимающий свойство `name` и отображающий приветствие:

```rust
#[component]
pub fn MyComponent(name: String) -> Element {
    rsx! {
        div {
            h3 { "Hello, {name}!" }
        }
    }
}
```

## Использование компонентов в RSX

Определив компонент, можно использовать его в разметке RSX так же, как любой другой элемент:

```rust
rsx! {
        MyComponent { name: "World" }
    }
```

> Хотя компоненты определяются как функции, их не следует вызывать как обычные функции. Когда вы используете компонент в RSX, Dioxus создаёт новый экземпляр компонента, который управляет своим собственным состоянием и жизненным циклом.

## Свойства компонента

Свойства компонента — это объект, передаваемый компоненту при его рендеринге. Эти свойства похожи на аргументы функции — поэтому поля свойств определяются как аргументы функции в компонентах. В некоторых случаях может быть полезно вынести свойства компонента в отдельную структуру. Вместо определения свойств встроенными, можно просто использовать аргумент с именем "props" и затем определить свойства в сопутствующей структуре.

```rust
#[derive(PartialEq, Clone, Props)]
struct CardProps {
  title: String,
  content: String
}

#[component]
fn Card(props: CardProps) -> Element {
  rsx! {
      h1 { "{props.title}" }
      span { "{props.content}" }
    }
}
```

Когда мы выносим свойства в структуру, нужно убедиться, что структура реализует три обязательных трейта:
- `PartialEq`: используется для определения, нуждается ли компонент в повторном рендеринге
- `Clone`: при каждом рендере объект свойств клонируется
- `Props`: выводит трейт `Properties`, который Dioxus использует для рендеринга и сборки

Каждая из этих границ имеет последствия для структурирования свойств нашего компонента.

### PartialEq

`PartialEq` используется Dioxus runtime для определения, изменились ли свойства компонента из-за какого-либо действия пользователя. Поскольку компоненты вызываются другими компонентами, небольшие изменения свойств выше по дереву компонентов могут вызвать каскад работы для runtime Dioxus. Реализация `PartialEq` используется для минимизации объёма работы, которую runtime Dioxus должен проделать при реагировании на эти изменения.

Для продвинутых случаев может быть полезно настроить `PartialEq` реализацию свойств для производительности. Например, можно сравнивать большие наборы данных только по их ID, а не по фактическому содержимому. В таких случаях мы вручную реализуем трейт `PartialEq`, чтобы пропустить проверку равенства набора данных:

```rust
#[derive(Clone, Props)]
struct DatasetViewer {
  id: Uuid,
  contents: Vec<u8>
}

impl PartialEq for DatasetViewer {
  fn eq(&self, other: &Self) -> bool {
      self.id.eq(&other.id)
  }
}
```

Многие утилиты Dioxus используют сравнение по указателю вместо сравнения по содержимому для повышения производительности.

### Clone

Граница `Clone` — особенно интересное требование для свойств компонента. Архитектура дерева компонентов Dioxus построена на идее "однонаправленного потока данных" (unidirectional data flow). Это паттерн проектирования, который предотвращает изменение входных свойств компонентами ниже по дереву. Предотвращая случайные мутации, пользовательские интерфейсы обычно содержат меньше ошибок. Rust сам решает эту проблему через систему borrow checker, но borrow checker плохо работает с асинхронными задачами, которые довольно распространены в разработке приложений.

Обычно клонировать большинство свойств компонентов — нормально, но некоторые объекты могут быть слишком дорогими для клонирования и негативно сказываться на производительности. В большинстве случаев можно просто обернуть значение в тип обёртки [`ReadSignal`] и объект будет автоматически обёрнут в умный указатель:

```rust
// раньше...
struct CardProps {
  content: String
}

// с ReadSignal:
struct CardProps {
  content: ReadSignal<String>
}
```

К счастью, со стороны вызывающего кода изменений не требуется:

```rust
rsx! {
  CardProps {
    content: query.content()
  }
}
```

Обратите внимание, что `ReadSignal` — не единственный доступный умный указатель. Умные указатели Rust (Arc, Rc) также делают клонирование дешевле, как и пользовательская реализация `Clone`.

### Props

Макрос `Props` реализует трейт `Properties` для объекта свойств. Этот трейт и его реализация являются деталью реализации в Dioxus и обычно не предназначены для ручной реализации. Макрос `Props` полезен, поскольку выводит строго типизированный билдер для Properties. Мы можем использовать этот билдер даже вне RSX:

```rust
let props = CardProps::builder().content("body".to_string()).build();
```

## Макрос `#[component]`

Свойства можно модифицировать для приёма более широкого спектра входных данных, чем обычный аргумент функции. Мы не будем здесь рассматривать все детали, но информацию можно найти в документации [макроса component](https://docs.rs/dioxus/latest/dioxus/prelude/attr.component.html).

Например, компонент `Link` из Dioxus Router активно использует модификаторы:

```rust
/// Свойства для [`Link`].
#[derive(Props, Clone, PartialEq)]
pub struct LinkProps {
    /// Атрибут class для тега `a`.
    pub class: Option<String>,

    /// Класс, применяемый к сгенерированному HTML-якорному тегу, если целевой маршрут активен.
    pub active_class: Option<String>,

    /// Дочерние элементы для рендеринга внутри сгенерированного HTML-якорного тега.
    pub children: Element,

    /// Когда [`true`], целевой маршрут будет открыт в новой вкладке.
    ///
    /// Это не меняет, активна ли [`Link`] или нет.
    #[props(default)]
    pub new_tab: bool,

    /// Обработчик события onclick.
    pub onclick: Option<EventHandler<MouseEvent>>,

    /// Должно ли выполняться поведение по умолчанию, если предоставлен обработчик `onclick`.
    ///
    /// 1. Когда `onclick` — [`None`] (по умолчанию, если не указано), `onclick_only` не имеет эффекта.
    /// 2. Если `onclick_only` — [`false`] (по умолчанию, если не указано), предоставленный обработчик `onclick`
    ///    будет выполнен после обычной функциональности ссылки.
    /// 3. Если `onclick_only` — [`true`], будет выполнен только предоставленный обработчик `onclick`.
    #[props(default)]
    pub onclick_only: bool,

    /// Атрибут rel для сгенерированного HTML-якорного тега.
    ///
    /// Для внешних `a` по умолчанию — `noopener noreferrer`.
    pub rel: Option<String>,

    /// Цель навигации. Примерно эквивалентен атрибуту href HTML-якорного тега.
    #[props(into)]
    pub to: NavigationTarget,

    #[props(extends = GlobalAttributes)]
    attributes: Vec<Attribute>,
}
```

Можно использовать атрибут `#[props()]` для каждого поля, чтобы модифицировать свойства, которые принимает ваш компонент:

- [`#[props(default)]`](https://docs.rs/dioxus/latest/dioxus/prelude/attr.component.html#default-props) — Делает поле опциональным в компоненте и использует значение по умолчанию, если оно не задано при создании компонента.
- [`#[props(!optional)]`](https://docs.rs/dioxus/latest/dioxus/prelude/attr.component.html#optional-props) — Делает поле с типом `Option<T>` обязательным.
- [`#[props(into)]`](https://docs.rs/dioxus/latest/dioxus/prelude/attr.component.html#converting-props) — Преобразует поле в правильный тип с помощью трейта [`Into`].
- [`#[props(extends = GlobalAttributes)]`](https://docs.rs/dioxus/latest/dioxus/prelude/attr.component.html#extending-elements) — Расширяет свойства всеми атрибутами из элемента или глобальных атрибутов элемента.

Свойства также ведут себя немного иначе при использовании с:

- [`Option<T>`](https://docs.rs/dioxus/latest/dioxus/prelude/attr.component.html#optional-props) — Поле автоматически становится опциональным со значением по умолчанию `None`.
- [`ReadOnlySignal<T>`](https://docs.rs/dioxus/latest/dioxus/prelude/attr.component.html#reactive-props) — Макрос props автоматически преобразует `T` в `ReadOnlySignal<T>` при передаче как prop.
- [`String`](https://docs.rs/dioxus/latest/dioxus/prelude/attr.component.html#formatted-props) — Макрос props будет принимать форматированные строки для любого поля свойства с типом `String`.
- [`children: Element`](https://docs.rs/dioxus/latest/dioxus/prelude/attr.component.html#children-props) — Макрос props будет принимать дочерние элементы, если вы включаете свойство `children`.
- `EventHandler<T>` — принуждает к использованию замыканий

Обратите внимание, что эти атрибуты работают как для определений свойств на основе структур, так и для встроенных определений:

```rust
#[component]
fn Link(
  /// Когда [`true`], целевой маршрут будет открыт в новой вкладке.
  #[props(default)]
  new_tab: bool,

  /// Цель навигации. Примерно эквивалентен атрибуту href HTML-якорного тега.
  #[props(into)]
  to: NavigationTarget,
) -> Element {
  ...
}
```

Поскольку комментарии документации обрабатываются макросом `#[component]`, они становятся доступными как встроенная документация при вызове компонента:

## Распространение свойств

Для большей компонуемости мы можем создавать свойства компонента вручную, а затем передавать их напрямую, используя синтаксис распространения Rust с `..some_props`.

```rust
let props = CardProps::lorem_ipsum();
rsx! {
  Card { ..props }
}
```

Этот механизм ведёт себя аналогично распространению структур в Rust, позволяя переопределять различные поля распространённого объекта, включая значения по умолчанию:

```rust
let props = CardProps::lorem_ipsum();
rsx! {
  Card { title: "Chapter 1", ..props }
}
```

## Дочерние элементы

Свойства имеют специальное поле "children", содержащее дочерние элементы компонента. Например, мы можем построить обёрточный компонент, который оборачивает своих детей в красный div. Этот компонент принимает специальный аргумент с именем "children", который является Element, используемым в выражениях RSX.

```rust
#[component]
fn RedDiv(children: Element) -> Element {
  rsx! {
    div {
      background_color: "red",
      {children}
    }
  }
}
```

При вызове компонента можно просто добавить вложенные дочерние элементы, как у обычного элемента:
```rust
rsx! {
  RedDiv {
    h1 { "Lorem Ipsum Dolor" }
    p { "..." }
  }
}
```
