# Веб-сокеты

Dioxus Fullstack предоставляет встроенные типы для создания и управления веб-сокетами, которые работают вместе с серверными функциями. Веб-сокеты Dioxus построены поверх базового API веб-сокетов Axum, но с несколькими улучшениями, адаптированными для fullstack-приложений:

- Общие типы для сервера и клиента
- Реактивные обёртки для использования в UI-коде
- Типизированные входные и выходные данные, а также настраиваемое кодирование

Веб-сокеты — чрезвычайно мощный коммуникационный протокол, который позволяет двунаправленную передачу сообщений к серверу и от него. Веб-сокеты эффективнее, чем HTTP-запросы, для большого количества сообщений, обеспечивают лучшую поддержку реального времени и позволяют *упорядоченную* передачу данных.

Обратите внимание, что веб-сокеты *сохраняют состояние*, то есть соединение веб-сокета связывает клиента и сервер для данной сессии. Если вы планируете использовать веб-сокеты в «бессерверной» среде с ограничениями по времени обработки запросов, то вам понадобится какой-то способ «сохранить» сессию веб-сокета между несколькими запросами.

## Websocket и WebsocketOptions

Чтобы создать новую серверную функцию, возвращающую веб-сокет, просто используйте `WebsocketOptions` как тип вашего тела и `Websocket` как тип вашего ответа.

```rust
#[get("/api/uppercase_ws")]
async fn uppercase_ws(options: WebSocketOptions) -> Result<Websocket> {
    Ok(options.on_upgrade(move |mut socket| async move {
        // отправляем приветственное сообщение
        _ = socket
            .send("Hello!".to_string())
            .await;

        // Цикл и эхо-ответ заглавными буквами
        while let Ok(msg) = socket.recv().await {
            _ = socket.send(msg.to_ascii_uppercase()).await;
        }
    }))
}
```

Тип `Websocket` обобщён по трём параметрам — типу входных данных, типу выходных данных и кодировке:

```rust
pub struct Websocket<In = String, Out = String, E = JsonEncoding> {
    ...
}
```

Типы входных и выходных данных — это типы, используемые при вызове `.send()` и `.recv()` на объекте `socket`, предоставляемом после `on_upgrade`. Благодаря сильной типизации веб-сокета мы гарантируем, что ваш клиент и сервер всегда используют правильный формат сообщений на клиенте и сервере.

Метод `on_upgrade` — это обёртка над базовым Axum API `on_upgrade`, который возвращает axum-ответ, сообщая клиенту, что процесс обновления веб-сокета прошёл успешно. Если клиент согласен, то сервер запустит колбэк `on_upgrade`, породив фьючер. Обратите внимание, что этот фьючер порождается в tokio [LocalSet](https://docs.rs/tokio/latest/tokio/task/struct.LocalSet.html). Это означает, что фьючеру не нужно быть `Send`.

Мы можем использовать свои собственные типы сообщений для входных и выходных сообщений. Вызовы `.send()` и `.recv()` будут пытаться десериализовать сообщения в правильный тип, возвращая ошибку, если десериализация не удалась.

```rust
// События, текущие *от* клиента *к* серверу
#[derive(Serialize, Deserialize, Debug)]
enum ClientEvent {
    TextInput(String),
}

// События, текущие *к* клиенту *от* сервера
#[derive(Serialize, Deserialize, Debug)]
enum ServerEvent {
    Uppercase(String),
}

#[get("/api/uppercase_ws")]
async fn uppercase_ws(options: WebSocketOptions) -> Result<Websocket<ClientEvent, ServerEvent>> {
    ...
}
```

Мы также можем настраивать кодировку веб-сокета с помощью третьего обобщения на `Websocket`. По умолчанию сообщения кодируются с использованием JSON с `JsonEncoding`, но вы можете выбрать альтернативный формат, например бинарный формат Cbor с `CborEncoding`:

```rust
#[get("/api/uppercase_ws")]
async fn uppercase_ws(options: WebSocketOptions) -> Result<Websocket<ClientEvent, ServerEvent, CborEncoding>> {
    ...
}
```

Как правило, если вы работаете только с клиентами на Rust, то Cbor или MsgPack — лучшие варианты, но сторонние клиенты могут лучше подходить под стандартную JSON-кодировку.

Если вам нужно отправить дополнительные детали на сервер перед установлением соединения веб-сокета, вы можете использовать параметры пути и запроса, а также извлечение заголовков, как обычно.

```rust
#[get("/api/uppercase_ws?name&age")]
async fn uppercase_ws(
    name: String,
    age: i32,
    options: WebSocketOptions,
) -> Result<Websocket<ClientEvent, ServerEvent, CborEncoding>> {
    ...
}
```

## Подключение к веб-сокету

На клиенте, чтобы подключиться к веб-сокету, мы просто вызываем серверную функцию и ожидаем результата. Вы можете сделать это внутри хука `use_future`, чтобы подключиться к эндпоинту веб-сокета при монтировании компонента:

```rust
// Вызов `.recv()` автоматически ожидает установления соединения и десериализует
// сообщения по мере их поступления.
use_future(move || async move {
    // Подключаемся к веб-сокету
    let socket = uppercase_ws(WebSocketOptions::new()).await;

    // Ожидаем следующее сообщение с помощью `.recv()`
    while let Ok(msg) = socket.recv().await {
        messages.push(msg);
    }
});
```

Объект `Websocket` имеет ряд служебных методов, которые вы можете использовать для оценки состояния соединения, отправки сообщений и получения сообщений. Мы предоставляем ряд низкоуровневых API, таких как `send_raw`, которые позволяют отправлять необработанные (raw) фреймы веб-сокета, если типизированный API слишком строг.



## Хук use_websocket

Вы могли заметить в примере с `use_future` выше, что веб-сокет доступен только внутри содержащей его области видимости. В реальном приложении вы захотите отправлять сообщения в веб-сокет и реагировать на любые изменения статуса подключения.

Хук `use_websocket` оборачивает объект `websocket` с сигнальной реактивностью. Мы можем использовать `.status()` для чтения состояния соединения веб-сокета и `.send()` для отправки сообщений на сервер.

Чтобы подключиться к веб-сокету, мы можем использовать `use_websocket`:

```rust
// `use_websocket` оборачивает соединение `WebSocket` и предоставляет реактивный хэндл для лёгкой
// отправки и получения сообщений и отслеживания состояния соединения.
//
// Мы можем настраивать соединение веб-сокета с помощью структуры `WebSocketOptions`, позволяя нам
// устанавливать такие вещи, как пользовательские заголовки, протоколы, стратегии переподключения и т. д.
let mut socket = use_websocket(|| uppercase_ws("John Doe".into(), 30, WebSocketOptions::new()));
```

Чтобы слушать сообщения, мы можем использовать `.recv()` в фьючере:

```rust
// Вызов `.recv()` автоматически ожидает установления соединения и десериализует
// сообщения по мере их поступления.
use_future(move || async move {
    while let Ok(msg) = socket.recv().await {
        messages.push(msg);
    }
});
```

А затем, чтобы отправлять сообщения, мы можем использовать `.send()` на хэндле:

```rust
rsx! {
    input {
        placeholder: "Введите сообщение",
        oninput: move |e| async move {
            _ = socket.send(ClientEvent::TextInput(e.value())).await;
        },
    }
}
```

Если соединение не удаётся, вы можете перезапустить его, вручную вызвав `.set()` на хэндле с новым объектом веб-сокета.
