# Аутентификация

Большинство production-ready приложений имеют какую-либо аутентификацию и авторизацию для ограничения доступа к данным и ресурсам, чтобы они не были публично доступны всем пользователям.

Dioxus *не* предоставляет встроенный способ управления аутентификацией. Однако, поскольку аутентификация является таким критически важным компонентом при создании fullstack-приложений, эта глава поможет вам в процессе её реализации для вашего приложения.

> В будущем мы хотели бы интегрировать сессии и аутентификацию напрямую в Dioxus Fullstack, но пока что вам придётся полагаться на сторонние библиотеки.

## Что такое аутентификация?

Аутентификация — это процесс проверки личности пользователя, обычно с помощью cookies или токенов доступа.

Ваше приложение не должно слепо принимать действия от ненадёжных пользователей, поэтому важно проверить, что пользователь, который утверждает, что он «Боб», *действительно является* «Бобом».

## Что такое авторизация?

Авторизация — это *следующий шаг* после аутентификации. Как только личность пользователя подтверждена, вы должны затем проверить, что он действительно может совершить данное действие.

Вы не хотите, чтобы один пользователь изменил учётные данные другого пользователя, поэтому любое действие, связанное с пользовательскими данными, должно быть сначала *авторизовано*.

## Аутентификация построена на сессиях

В основе аутентификации лежит ассоциация *подключения* пользователя с некоторой *сессией* в базе данных. По мере того как пользователь перемещается по нашей странице и совершает действия, нам нужен какой-то способ идентифицировать его сессию на сервере.

Обычно это делается через промежуточное ПО, которое автоматически регистрирует каждое подключение со строкой в вашей базе данных. Если пользователь *не аутентифицирован*, вы можете либо сохранить его сессию как анонимного пользователя, либо полностью игнорировать её.

Сессия обычно вставляется с помощью промежуточного ПО на уровне axum:

```rust
dioxus::server::router(app)
    .layer(axum::middleware::from_fn(
        |request: Request, next: Next| async move {
            // Получаем auth-токен, а затем вставляем сессию в расширения запроса
            //
            // Нам нужно найти auth-токен в нашей базе данных, чтобы получить сессию
            if let Some(token) = request.headers().get("Authorization") {
                if let Some(session) = DATABASE.get_session(token) {
                    request.extensions_mut().insert(session);
                }
            }

            // И затем запускаем запрос
            next.run(request).await
        },
    ))
```

## Библиотеки для аутентификации

Вы можете реализовать поиск сессий и систему создания сессий вручную, или использовать стороннюю библиотеку, например [`axum_session_auth`](https://crates.io/crates/axum_session_auth), чтобы справиться с большей частью сложности за вас.

Как правило, вы добавите стороннюю библиотеку как `.layer()` на ваш роутер, и она автоматически добавит расширение `Session` к вашим запросам:

```rust
dioxus::serve(|| async move {
    // Создаём axum-роутер, к которому dioxus прикрепит приложение
    Ok(dioxus::server::router(app)
        // Добавляем `AuthLayer`
        .layer(
            AuthLayer::new(Some(db.clone()))
                .with_config(AuthConfig::<i64>::default().with_anonymous_user_id(Some(1))),
        )
        // И добавляем `SessionLayer`
        .layer(SessionLayer::new(
            SessionStore::<SessionSqlitePool>::new(
                Some(db.into()),
                SessionConfig::default().with_table_name("test_table"),
            )
            .await?,
        )))
})
```

Крейт `axum_session_auth` интегрируется с `sqlx` для автоматического управления сессиями с помощью строки в вашей базе данных.


## Аутентификация как экстрактор

Вы можете использовать экстракторы для интеграции аутентификации с вашим Fullstack-приложением.

Вы можете создать пользовательский экстрактор для извлечения сессии аутентификации из запроса. Из этой сессии аутентификации вы можете проверить, есть ли у пользователя необходимые привилегии, прежде чем возвращать приватные данные.

Поскольку сессии вставляются в каждый запрос, вы можете извлекать их с помощью серверных экстракторов:

```rust
/// Мы используем экстрактор `auth::Session` для получения доступа к текущей пользовательской сессии.
/// Это позволяет нам модифицировать пользовательскую сессию, входить/выходить и получать доступ к текущему пользователю.
#[post("/api/user/login", auth: auth::Session)]
pub async fn login() -> Result<()> {
    auth.login_user(2);
    Ok(())
}

/// Так же, как `login`, но на этот раз мы разлогиниваем пользователя.
#[post("/api/user/logout", auth: auth::Session)]
pub async fn logout() -> Result<()> {
    auth.logout_user();
    Ok(())
}
```

[Полный пример аутентификации](https://github.com/DioxusLabs/dioxus/blob/7102bc3b6a0ddea3a9e71423fc6d667df8d956f3/examples/07-fullstack/auth/src/main.rs) с полной реализацией доступен в примерах fullstack.

## Аутентификация как сторонний сервис

Реализация аутентификации может быть несколько утомительной, поэтому существует ряд сторонних сервисов, которые упрощают реализацию для вас. С этими сервисами данные сессии и аутентификации, как правило, живут не в *вашей базе данных*, а в их.

Мы не рекомендуем какой-либо конкретный сторонний сервис. Однако существуют такие решения, как Supabase и Firebase, где сессии управляются в вашей базе данных, но с готовой инфраструктурой для интеграции.
