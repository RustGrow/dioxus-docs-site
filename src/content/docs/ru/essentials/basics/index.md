# Основы состояния

Теперь, когда вы знаете, как создавать пользовательские интерфейсы в Dioxus, пришло время узнать о создании и обновлении состояния вашего приложения.

**Управление состоянием — это, безусловно, самая сложная часть создания приложения.**

Это руководство проведёт вас через основные принципы управления состоянием в Dioxus с ранним акцентом на теорию, а затем перейдёт к практике.


## Теория управления состоянием

В конечном счёте, "управление состоянием" относится к действиям:

1. Инициализация данных для UI
2. Обработка событий от пользователя
3. Обновление данных и повторный рендеринг UI

Управление этим циклом легко вначале, но может стать более сложным по мере роста приложений, добавления асинхронной работы и взаимодействия с внешними ресурсами.

## Для опытных веб-разработчиков

Если вы приходите в Dioxus как опытный веб-разработчик, мы надеемся, что вы почувствуете себя комфортно довольно быстро. Управление состоянием в Dioxus было вдохновлено такими проектами, как React, Preact, SolidJS и Svelte.

Dioxus использует реактивность на основе сигналов. В отличие от SolidJS, *чтение* и *запись* значений **явные**. В Rust нет эквивалента JavaScript Proxy, поэтому реактивность отслеживается вызовами `.read()` и `.write()`.

```rust
let mut count = use_signal(|| 0);

rsx! {
    button {
        onclick: move |_| *count.write() += 1,
        "Increment"
    }
    {count.read().to_string()}
}
```

Во многих случаях `.read()` неявный, например, при использовании значения внутри строкового формата:

```rust
rsx! { "Count: {count}" }
```

В отличие от Svelte, Dioxus не делает compile-time трансформацию вашего состояния. В отличие от SolidJS, компоненты Dioxus запускаются несколько раз. Вы можете думать об управлении состоянием в Dioxus как о гибриде React и SolidJS, где реактивность отслеживается автоматически, но компоненты могут свободно запускаться несколько раз в течение своей жизни.

Dioxus также использует "здравый смысл" оптимизации, такие как автоматическая мемоизация свойств и автоматическое отслеживание реактивности — два огромных улучшения по сравнению с React. Dioxus также позволяет вам делать ранний возврат, опционально с Suspended future, давая вам модель `async/await` для загрузки данных в компонентах.

## Для опытных Rust-разработчиков

Если вы приходите в Dioxus как опытный Rust-разработчик, вы можете быть озадачены нашим использованием "необычных" примитивов, таких как `use_signal`, `use_memo`, `use_resource` и т.д. Dioxus использует stateful "хуки" — парадигма, которая имеет свои корни в веб-разработке (в частности, React).

Если вы не хотите писать React-подобный код в Dioxus, вы можете использовать структуры для хранения состояния и обрабатывать обновления UI императивно. Вы можете хранить ваше состояние в структуре:

```rust
struct EditorState {
    text: String
}

impl EditorState {
    fn handle_input(&mut self, event: FormEvent) {
        self.text = event.value();
    }
}
```

А затем использовать это состояние в компоненте с единственным `use_signal`:

```rust
/// Определить компонент
#[component]
fn TextEditor() -> Element {
    // Использовать единственный "state" объект, обёрнутый в `Signal`
    let mut state = use_signal(EditorState::new);

    rsx! {
        input {
            // В обработчиках событий вызывать `.write()`, чтобы получить `&mut self` на "state" объект
            oninput: move |event| state.write().handle_input(event)
        }
    }
}
```

Borrow checker Rust добавляет сложности при хранении значений между асинхронными задачами и коллбэками. Использование наших встроенных примитивов решает ряд проблем:

- Возможность ссылаться на данные в `'static` задачах и коллбэках
- Вызовы `.write()` автоматически ставят компонент в очередь на повторный рендеринг
- Значения никогда не "устаревают", даже в асинхронных контекстах.

Dioxus предоставляет свои основные функции рантайма, такие как `spawn` и `needs_update` — подход, который Rust-разработчики могут знать лучше. Встроенные реактивные примитивы интеллектуально используют эти функции, и поэтому, вероятно, будут более эффективны, чем упрощённый подход к состоянию, но имеют кривую обучения.
