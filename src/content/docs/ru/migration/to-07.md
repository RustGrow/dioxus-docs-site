# Как обновиться до Dioxus 0.7

В этом руководстве описаны изменения API между релизами 0.6 и 0.7. Релиз 0.7 содержит критические изменения в:

- [`dioxus‑lib`](#удаление-dioxuslib)
- [Отправке форм](#поведение-отправки-форм)

- [Кодеке серверных функций по умолчанию](#изменение-кодека-серверных-функций-по-умолчанию-на-json)

## Удаление `dioxus‑lib`

Крейт `dioxus‑lib` был удалён. Вам нужно добавить dioxus как зависимость и изменить все ссылки с `dioxus_lib` на прямое использование `dioxus`.

```toml
# Cargo.toml
[dependencies]
dioxus = { version = "0.7", default-features = false, features = ["lib"] }
```

```rust
// src/main.rs
use dioxus::prelude::*;
```

[PR №4438](https://github.com/DioxusLabs/dioxus/pull/4438)

## Поведение отправки форм

До dioxus 0.7 отправка форм по умолчанию предотвращалась во всех рендерерах, так как это ломало страницу на десктопе. Если вы вызывали `prevent_default` при отправке формы, это инвертировало поведение по умолчанию и позволяло форме отправиться.

В dioxus 0.7 поведение по умолчанию — разрешить отправку форм, и вам нужно вызвать `prevent_default`, чтобы предотвратить её. Десктопный рендерер отдельно предотвращает всю навигацию по странице, включая отправку форм.

Dioxus 0.6:
```rust
rsx!(
    form {
        onsubmit: |e| {}, // Раньше формы автоматически не отправлялись и не перезагружали страницу
        input { name: "username", type: "text" },
        button { type: "submit", "Submit" }
    }
)
```

Dioxus 0.7:
```rust
rsx!(
    form {
        onsubmit: |e| e.prevent_default(), // В dioxus 0.7 нужно вызвать prevent_default, чтобы предотвратить отправку формы
        input { name: "username", type: "text" },
        button { type: "submit", "Submit" }
    }
)
```

[PR №4422](https://github.com/DioxusLabs/dioxus/pull/4422)

## Опции ассетов

API опций ассетов для manganis было унифицировано с использованием единого `AssetOptionsBuilder`. Вместо подключения конкретных опций, таких как `ImageAssetOptions::new()`, теперь можно использовать `AssetOptions::image()`, чтобы создать билдер для нужного варианта ассета.

Dioxus 0.6:
```rust
use manganis::{ImageFormat, ImageAssetOptions, Asset, asset, ImageSize};

pub const RESIZED_PNG_ASSET: Asset =
    asset!("/assets/image.png", ImageAssetOptions::new().with_size(ImageSize::Manual { width: 52, height: 52 }));
pub const AVIF_ASSET: Asset = asset!("/assets/image.png", ImageAssetOptions::new().with_format(ImageFormat::Avif));
```

Dioxus 0.7:
```rust
use manganis::{ImageFormat, ImageAssetOptions, Asset, asset, ImageSize};

pub const RESIZED_PNG_ASSET: Asset =
    asset!("/assets/image.png", AssetOptions::image().with_size(ImageSize::Manual { width: 52, height: 52 }));
pub const AVIF_ASSET: Asset = asset!("/assets/image.png", AssetOptions::image().with_format(ImageFormat::Avif));
```

[PR №4312](https://github.com/DioxusLabs/dioxus/pull/4312)

### Пользовательский тип ошибки серверной функции

Тип `ServerFnError` был изменён с универсального типа ошибки серверной функции на специфичный для dioxus тип ошибки, который легко преобразуется в `dioxus::Error`. Название типа осталось тем же, но вам может потребоваться обновить импорты, чтобы использовать тип dioxus вместо типа серверной функции.

[PR №4205](https://github.com/DioxusLabs/dioxus/pull/4205)

### Элементы, удалённые из prelude

Многие элементы были удалены из prelude и теперь требуют явного импорта. К ним относятся:
- `use_drop`
- `Runtime`
- `queue_effect`
- `provide_root_context`

[PR №4128](https://github.com/DioxusLabs/dioxus/pull/4128)

### Изменение кодека серверных функций по умолчанию на JSON

Серверные функции раньше кодировали аргументы с использованием URL-кодированных данных формы. URL-кодирование не позволяло передавать пустые или вложенные структуры данных. Кодеком по умолчанию теперь является JSON, который поддерживает гораздо больше типов. Сторонние интеграции, зависящие от старого формата кодирования форм, должны быть обновлены для использования JSON-кодека, или вам нужно явно установить протокол в `Http<PostUrl, Json>`.

Dioxus 0.6:
```rust
#[server]
async fn my_post_function(arg: MyStruct) -> ServerFnResult<MyResponse> {
    ...
}

#[server(protocol = Http<Json, Json>)]
async fn my_json_function(arg: MyStruct) -> ServerFnResult<MyResponse> {
    ...
}
```

Dioxus 0.7:
```rust
#[server(protocol = Http<GetUrl, Json>)]
async fn my_post_function(arg: MyStruct) -> ServerFnResult<MyResponse> {
    ...
}
#[server]
async fn my_json_function(arg: MyStruct) -> ServerFnResult<MyResponse> {
    ...
}
```

[PR №3602](https://github.com/DioxusLabs/dioxus/pull/3602)

### Транзитивные обновления зависимостей

Несколько крейтов, которые dioxus экспортирует в публичных API и реэкспортирует, были обновлены до последних версий. Если вы зависите от этих крейтов, вам может потребоваться обновить ваши зависимости.

- Wry обновлён до 0.52: [PR №4255](https://github.com/DioxusLabs/dioxus/pull/4255)
- Axum обновлён до 0.8: [PR №3820](https://github.com/DioxusLabs/dioxus/pull/3820)
- Server fn обновлён до 0.7: [PR №3560](https://github.com/DioxusLabs/dioxus/pull/3560)

## Тип обработчика событий с владением (применяется только к пользовательским рендерам)

Обработчики HTML-событий Dioxus раньше принимали тот же копируемый обработчик событий, что и компоненты, что усложняло логику удаления (drop) в типе VNode. Теперь обработчики событий принимают `impl ::dioxus_core::prelude::SuperInto<::dioxus_core::ListenerCallback<$data>, __Marker>` вместо `impl ::dioxus_core::prelude::SuperInto<::dioxus_core::prelude::EventHandler<::dioxus_core::Event<$data>>, __Marker>`. Пользовательские рендереры должны быть обновлены для принятия того же типа для консистентности.

[PR №4289](https://github.com/DioxusLabs/dioxus/pull/4289)
