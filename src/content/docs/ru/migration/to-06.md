# Как обновиться до Dioxus 0.6

В этом руководстве описаны изменения API между релизами `0.5` и `0.6`. Релиз `0.6` содержит критические изменения в:

- Типе `Element`
- Предотвращении поведения по умолчанию (prevent default)
- Ассетах с Manganis
- Интеграции `dioxus_logger` с `dioxus`
- Функции `launch`
- Функции `eval`
- Крейте `dioxus-fullstack`
- Крейте роутера
- Макросе `derive(Props)`
- Крейте `dioxus-core`
- API пользовательских рендереров
- Глобальном управлении состоянием

## Element

Тип элемента изменён с `Option<VNode>` на `Result<VNode, RenderError>`. Это позволяет распространять ошибки при рендеринге с помощью оператора `?`, но убирает возможность возвращать `None` из компонента. Вместо возврата `None` вы можете вернуть `VNode::empty()` или пустой макрос `rsx!`.

Dioxus 0.5:

```rust
use dioxus::prelude::*;

fn app() -> Element {
    let number = use_signal(|| -1);

    if number() < 0 {
        // ❌ В dioxus 0.6 тип элемента — Result, поэтому значения None нельзя возвращать напрямую
        return None;
    }

    rsx! {
        "Positive number: {number}"
    }
}
```

Dioxus 0.6:

```rust
use dioxus::prelude::*;

    fn app() -> Element {
        let number = use_signal(|| -1);

        if number() < 0 {
✅ You can return VNode::empty() instead
            return VNode::empty();
        }
        if number() < 0 {
✅ Or an empty rsx! macro
            return rsx! {};
        }

        rsx! {
            "Positive number: {number}"
        }
    }
```

## Prevent Default

Dioxus 0.1–0.5 использовал атрибут `prevent_default` для предотвращения поведения по умолчанию обработчиков событий для каждого события. Dioxus 0.6 вводит более тонкий контроль над предотвращением поведения по умолчанию с помощью функции `prevent_default` на типе события. Вместо установки атрибута `prevent_default` для всех событий, которые вы хотите предотвратить, вы можете создавать обработчики событий, вызывающие `event.prevent_default()`.

Dioxus 0.5:

```rust
use dioxus::prelude::*;

    fn app() -> Element {
        rsx! {
            a {
                href: "https://dioxuslabs.com",
❌ The prevent default attribute is deprecated in dioxus 0.6
                prevent_default: "onclick",
                "Don't navigate to dioxuslabs.com"
            }
        }
    }
```

Dioxus 0.6:

```rust
use dioxus::prelude::*;

    fn app() -> Element {
        rsx! {
            a {
                href: "https://dioxuslabs.com",
✅ Instead, you can call event.prevent_default() inside the event handler
                onclick: move |event| event.prevent_default(),
                "Don't navigate to dioxuslabs.com"
            }
        }
    }
```

> Примечание: поскольку обработчики событий выполняются на сервере в Liveview, события нельзя быстро предотвратить внутри обработчика события. Поэтому новый метод `prevent_default` не предотвращает поведение по умолчанию в Liveview.
>
> Вместо этого вы можете использовать JavaScript внутри обработчика `onclick` для предотвращения поведения по умолчанию.
>
> ```rust
> ```rust
use dioxus::prelude::*;

    fn app() -> Element {
        rsx! {
            a {
                href: "https://dioxuslabs.com",
✅ In liveview, you can use javascript to prevent default behavior
                "onclick": "event.preventDefault()",
                "Don't navigate to dioxuslabs.com"
            }
        }
    }
```
> ```

## Ассеты

Синтаксис макроса `asset!` изменился в Dioxus 0.6. Вместо приёма одного аргумента с путём и конфигурацией ассета теперь можно передавать путь первым аргументом, а конфигурацию — необязательным вторым аргументом.

Также изменился путь, который принимает макрос `asset!`. Раньше макрос принимал абсолютные и относительные пути, где относительные пути были относительно текущей директории крейта. Теперь макрос принимает только абсолютные пути, которые разрешаются относительно корня крейта.

Dioxus 0.5:

```rust
use dioxus::prelude::*;

fn app() -> Element {
    rsx! {
        img {
            src: asset!(image("./assets/static/bundle.png").size(100, 100))
        }
    }
}
```

Dioxus 0.6:

```rust
use dioxus::prelude::*;

    fn app() -> Element {
        rsx! {
            img {
                src: asset!("/assets/static/bundle.png", ImageAssetOptions::new().with_size(ImageSize::Manual { width: 100, height: 100 }))
            }
        }
    }
```

## Логирование

Dioxus 0.6 интегрирует крейт `dioxus-logger` непосредственно в dioxus.

Ранее вам нужно было добавить `dioxus-logger` в Cargo.toml и затем вызвать его функцию инициализации:

```rs
// cargo.toml:
// dioxus-logger = "0.5"

use dioxus::prelude::*;
use tracing::Level;

fn main() {
    // Инициализация логгера
    dioxus_logger::init(Level::INFO).expect("failed to init logger");

    // Код запуска Dioxus
    dioxus::launch(app)
}
```

Теперь, в Dioxus 0.6, логгер инициализируется неявно при вызове `launch`. Просто вызовите launch, и логгер инициализируется с уровнем логирования по умолчанию. В режиме разработки устанавливается уровень трассировки `Debug`, а в релизе — только `Info`.

```rust
use dioxus::prelude::*;

fn main() {
    dioxus::launch(app);
}
```

Если вам всё ещё нужно установить уровень вручную или настроить кастомный subscriber, сделайте это перед вызовом `launch`. Мы экспортируем функцию `initialize_default` на случай, если вам нужно дополнительное логирование до вызова `launch`:

```rust
use dioxus::prelude::*;

fn main() {
    dioxus::logger::initialize_default();

    tracing::info!("Logs received!");

    dioxus::launch(app);
}
```

## Launch

Функция `launch` была удалена из prelude. Теперь вам нужно импортировать функцию запуска из `dioxus` или использовать её по полному пути:

```rust
use dioxus::prelude::*;

fn main() {
    ❌ launch(app);
    dioxus::launch(app); // ✅
}
```

См. <https://github.com/DioxusLabs/dioxus/pull/2967> для подробностей.

## Eval

- `eval` был перемещён из prelude в модуль `document`. Теперь его нужно вызывать через `document::eval` вместо `eval`:

```rust
use dioxus::prelude::*;

fn app() -> Element {
    ❌ use_effect(|| eval("console.log(1)"));
    use_effect(|| document::eval("console.log(1)")); // ✅

    rsx! {}
}
```

- Флаг feature `eval` был удалён из крейта `dioxus-html`, а функциональность `EvalProvider` была перемещена в новый крейт `dioxus-document`. Пользовательские рендереры теперь должны предоставлять контекст `Rc<dyn Document>` приложению, чтобы `eval` и head-элементы работали корректно. См. <https://github.com/DioxusLabs/dioxus/pull/2635> для подробностей.
- `Eval::recv` и `Eval::join` теперь возвращают любое значение, реализующее `DeserializeOwned`, вместо `serde_json::Value`. `Eval::send` теперь принимает любое значение, реализующее `Serialize`. См. <https://github.com/DioxusLabs/dioxus/pull/3035> для подробностей.

## Fullstack

- Фича `dioxus/axum` была переименована в `dioxus/server`.

```toml
[features]
default = []
# ❌ server = ["dioxus/axum"]
server = ["dioxus/server"] # ✅
web = ["dioxus/web"]
```

См. <https://github.com/DioxusLabs/dioxus/pull/3186> для подробностей.

- Элемент `fullstack::Config` был удалён. Теперь вы можете передавать конфигурации платформ непосредственно в `LaunchBuilder`. Например, если вы хотите установить rootname на каждой платформе, вы можете задать имя корня в каждой конфигурации:

```rust
LaunchBuilder::new()
    // Устанавливайте серверную конфигурацию только если включена фича server
    .with_cfg(server_only! {
        ServeConfigBuilder::default().root_id("app")
    })
    // Вам также нужно установить root id в веб-конфигурации
    .with_cfg(web! {
        dioxus::web::Config::default().rootname("app")
    })
    // И десктоп-конфигурации
    .with_cfg(desktop! {
        dioxus::desktop::Config::default().with_root_name("app")
    })
    .launch(app);
```

См. <https://github.com/DioxusLabs/dioxus/pull/2967> для подробностей.

- dioxus-cli теперь проксирует fullstack-приложения на порту за обратным прокси. Если у вас есть кастомный сервер axum, вы должны обслуживать своё приложение на порту, возвращаемом `dioxus_cli_config::server_port`, и по адресу, возвращаемому `dioxus_cli_config::server_ip`, или по полному адресу, возвращаемому `dioxus_cli_config::fullstack_address_or_localhost`, во время разработки:

```rust
#[cfg(feature = "server")]
#[tokio::main]
async fn main() {
    // Получаем адрес, на котором должен работать сервер. Если CLI запущен, CLI проксирует fullstack на основной адрес,
    // и мы используем сгенерированный адрес, который даёт нам CLI
    let address = dioxus_cli_config::fullstack_address_or_localhost();

    // Запускаем fullstack-приложение на адресе, который проксирует CLI
    let router = axum::Router::new()
        .serve_dioxus_application(ServeConfigBuilder::default(), App);

    let router = router.into_make_service();
    let listener = tokio::net::TcpListener::bind(address).await.unwrap();
    axum::serve(listener, router).await.unwrap();
}
```

См. <https://github.com/DioxusLabs/dioxus/pull/2258> для подробностей.

- `serve_dioxus_application` был изменён так, чтобы принимать компонент напрямую вместо фабрики виртуального DOM. См. <https://github.com/DioxusLabs/dioxus/pull/2515> для подробностей.
- `register_server_fns` был переименован в `register_server_functions`. См. <https://github.com/DioxusLabs/dioxus/pull/2515> для подробностей.
- `RenderHandleState::new` принимает новый аргумент `ServeConfig`. См. <https://github.com/DioxusLabs/dioxus/pull/2862> для подробностей.
- `ServeConfigBuilder::build` возвращает Result. Он может завершиться ошибкой при десктоп-сборках, если файл `index.html` не найден. Эту ошибку можно игнорировать в десктоп-сборках. Вы можете передать билдер напрямую в `serve_dioxus_application`, чтобы отдавать файл index.html только если он существует. См. <https://github.com/DioxusLabs/dioxus/pull/2862> для подробностей.
- `dioxus_fullstack::Config::addr` был удалён. Теперь вы можете экспортировать переменные окружения `PORT` и `IP`, чтобы задать адрес, который метод `launch` использует для сервера.

## Роутер

- Производный макрос `Routable` больше не принимает поля, отсутствующие в `route("/route")`, если включена веб-фича. См. <https://github.com/DioxusLabs/dioxus/pull/2159> для подробностей.
- Трейт `ToRouteSegments` в роутере был изменён: теперь он принимает `&self` вместо `self`. Это означает, что теперь вы можете реализовать его для `T` напрямую вместо `&T`. См. <https://github.com/DioxusLabs/dioxus/pull/2283> для подробностей.

## derive(Props)

- `#[props(into)]` игнорируется для любых строковых пропсов. Строковые пропсы уже принимают `impl ToString`, который реализован для многих тех же типов, но если вы реализуете `Into<String>` для конкретного типа, ваш код может потребовать изменений. См. <https://github.com/DioxusLabs/dioxus/pull/2501> для подробностей.
- Свойства, начинающиеся с заглавной буквы, больше не принимаются. Это позволяет нам автодополнять компоненты. См. <https://github.com/DioxusLabs/dioxus/pull/2652> для подробностей.

## Управление состоянием

- `use_coroutine` теперь принимает `impl FnMut` вместо `impl FnOnce`. Это было необходимо для поддержки перезапуска корутины без повторного выполнения компонента. См. <https://github.com/DioxusLabs/dioxus/pull/3005> для подробностей.
- `Signal::global_memo` теперь требует `T: PartialEq`, как и `use_memo`. См. <https://github.com/DioxusLabs/dioxus/pull/2851> для подробностей.
- `GlobalMemo<T>` теперь является псевдонимом трейта для `Global<Memo<T>, T>`, а `GlobalSignal<T>` — псевдонимом для `Global<Signal<T>, T>`. Чтобы получить базовый `Memo` или `Signal`, теперь можно использовать метод `resolve` вместо `signal` или `memo`. См. <https://github.com/DioxusLabs/dioxus/pull/2851> для подробностей.
- Трейт `Readable` в dioxus signals теперь требует метод `try_peek_unchecked` вместо `peek_unchecked`. См. <https://github.com/DioxusLabs/dioxus/pull/2714> для подробностей.
- Флаг feature `check_generation` был удалён из крейта `generational-box`. См. <https://github.com/DioxusLabs/dioxus/pull/2638> для подробностей.

## Изменения в ядре

- Поле `Template::name` было удалено. См. <https://github.com/DioxusLabs/dioxus/pull/2799> для подробностей.
- `Properties::into_vcomponent` теперь принимает только `render_fn` вместо `render_fn` и `component_name`. Это изменение исправляет имя реэкспортируемых компонентов. Исправления <https://github.com/DioxusLabs/dioxus/pull/2744>
- Поле `VNode::template` теперь имеет тип `Template` вместо `Cell<Template>`. См. <https://github.com/DioxusLabs/dioxus/pull/2705> для подробностей.
- `Mutations::sanitize` был переименован в `Mutations::sanitize`. См. <https://github.com/DioxusLabs/dioxus/pull/2653> для подробностей.
- Вариант `AttributeValue::Any` теперь содержит `Rc<dyn AnyValue>` вместо `Box<dyn AnyValue>`, чтобы сделать `AttributeValue` клонируемым (`Clone`). См. <https://github.com/DioxusLabs/dioxus/pull/2705> для подробностей.

## Пользовательские рендереры

Если вы разрабатываете пользовательский рендерер, вам следует знать о некоторых критических изменениях в горячей перезагрузке и rsx:

- Формат горячей перезагрузки CLI изменился значительно. Пользовательские рендереры должны перейти с `dioxus-hot-reload` на `dioxus_devtools`. Рендереры могут подключаться к движку горячей перезагрузки с помощью функции [connect](<https://docs.rs/dioxus>-devtools/0.6.0/dioxus_devtools/fn.connect.html). См. <https://github.com/DioxusLabs/dioxus/pull/2258> для подробностей.
- Формат кастомных элементов был изменён для улучшения автодополнения. Пространство имён `dioxus_elements` теперь должно содержать каждый элемент как модуль с константами `TAG_NAME` и `NAME_SPACE` внутри этого модуля. Каждый атрибут должен быть ещё одной константой в этом модуле. Верхнеуровневый модуль `dioxus_elements` должен содержать модуль `completions` с перечислением `CompleteWithBraces`, которое реэкспортирует каждый элемент, поддерживаемый пространством имён, для автодополнения фигурных скобок. См. <https://github.com/DioxusLabs/dioxus/pull/2421> для подробностей.
- Формат кастомных обработчиков событий изменился: добавлено `eventname::call_with_explicit_closure` для лучшего вывода типов в inline-замыканиях. См. <https://github.com/DioxusLabs/dioxus/pull/2437> для подробностей.

Если вы также используете dioxus-html, есть ещё несколько критических изменений:

- К трейту `FileEngine` был добавлен метод `file_size`. Любые пользовательские рендереры должны реализовать этот метод. См. <https://github.com/DioxusLabs/dioxus/pull/2323/files> для подробностей.
- У `HtmlEventConverter` появился новый метод `convert_resize_data`, который должен быть реализован любыми пользовательскими рендерерами, использующими dioxus-html. См. <https://github.com/DioxusLabs/dioxus/pull/2479> для подробностей.
- Веб- и нативные фичи были удалены из крейта `dioxus-html`. См. <https://github.com/DioxusLabs/dioxus/pull/3006> для подробностей.
- `dioxus_html::AttributeDescription` был переименован в `dioxus_html::AttributeDescription`. См. <https://github.com/DioxusLabs/dioxus/pull/2653> для подробностей.

## Мелкие критические изменения

В Dioxus 0.6 было ещё несколько мелких критических изменений:

- Многие неявные фичи из крейтов dioxus были удалены. Эти фичи автоматически генерировались cargo и обычно не были функциональны. См. <https://github.com/DioxusLabs/dioxus/pull/2512> для подробностей.
- `dioxus_autofmt::write_block_out` принимает `&CallBody` вместо `CallBody`. См. <https://github.com/DioxusLabs/dioxus/pull/2573> для подробностей.
- Фича `panic_hook`, которая предоставляет консольное сообщение при панике wasm, была перемещена из крейта `dioxus-web` в крейт `dioxus-logger`. Обработчик всё ещё предоставляется по умолчанию. См. <https://github.com/DioxusLabs/dioxus/pull/3302> для подробностей.
