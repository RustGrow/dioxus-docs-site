# Реактивные сигналы

В Dioxus UI вашего приложения определяется как функция его текущего состояния. По мере изменения состояния компоненты и эффекты, которые зависят от этого состояния, будут автоматически перезапускаться. Реактивность автоматически *отслеживает* состояние и *выводит* новое состояние, упрощая создание больших приложений, которые эффективны и просты для понимания.

Dioxus предоставляет единственный источник изменяемого состояния: **Сигнал**.

## Состояние с помощью сигналов

В Dioxus изменяемое состояние хранится в сигналах. Сигналы — это *отслеживаемые* значения, которые автоматически обновляют *реактивные контексты*, которые наблюдают за ними. Они являются источником состояния, из которого выводится все остальное состояние. Сигналы модифицируются напрямую обработчиками событий в ответ на пользовательский ввод или асинхронно в futures.

Вы можете создать сигнал с помощью хука `use_signal`:

```rust
let mut signal = use_signal(|| 0);
```

Как только у вас есть сигнал, вы можете получить ссылку на внутреннее значение сигнала, вызвав `.read()`:

```rust
let mut signal = use_signal(|| 0);

// используйте `.read()` для доступа к внутреннему значению
let inner = signal.read();
```

Для сигналов, чье внутреннее значение может быть дешево клонируемым, вы также можете использовать "функциональный" синтаксис для получения прямого `Clone` значения.

```rust
let name = use_signal(|| "Bob".to_string());

// Вызовите сигнал как функцию
let inner = name();

// Или используйте `.cloned()`
let inner = name.cloned();
```

Наконец, вы можете установить значение сигнала с помощью метода `.set()` или получить изменяемую ссылку на внутреннее значение с помощью метода `.write()`:

```rust
// Set the value from the signal
signal.set(1);

// get a mutable reference to the inner value with the .write() method
let mut value: &mut i32 = &mut signal.write();
*value += 1;
```

Простой компонент, который использует `.read()` и `.write()` для обновления своего собственного состояния с помощью сигналов, может выглядеть так:

```rust
fn Demo() -> Element {
    let mut count = use_signal(|| 0);

    // читаем текущее значение
    let current = count.read().clone();

    rsx! {
        button {
            onclick: move |_| *count.write() = current + 1,
            "Увеличить ({current})"
        }
    }
}
```

## Чтение сигналов

Сигналы можно читать несколькими способами:

1. `.read()` — возвращает ссылку на внутреннее значение
2. `.cloned()` — возвращает клон внутреннего значения
3. `()` — функциональный синтаксис, эквивалентный `.cloned()`

## Запись в сигналы

Сигналы можно модифицировать несколькими способами:

1. `.set(value)` — заменяет внутреннее значение
2. `.write()` — возвращает изменяемую ссылку на внутреннее значение
3. `.with_mut(|val| ...)` — изменяет значение через замыкание

## Сигналы и реактивность

Когда сигнал читается внутри компонента, Dioxus автоматически отслеживает эту зависимость. Если значение сигнала изменится, компонент будет перерисован.

```rust
fn ReactiveDemo() -> Element {
    let mut count = use_signal(|| 0);

    rsx! {
        div {
            "Счетчик: {count}"
            button {
                onclick: move |_| count += 1,
                "Увеличить"
            }
        }
    }
}
```

В этом примере, когда пользователь нажимает кнопку, `count` увеличивается, и компонент автоматически перерисовывается с новым значением.

## Локальные Подписки

Сигналы подписывают компоненты только тогда, когда вы читаете из сигнала внутри этого компонента. Сигнал никогда не подпишет компонент, если данные читаются внутри future или обработчика события.

```rust
fn App() -> Element {
    // Поскольку сигнал никогда не читается в этом компоненте,
    // этот компонент не будет перезапускаться при изменении сигнала
    let mut signal = use_signal(|| 0);

    rsx! {
        button {
            onclick: move |_| {
                signal += 1;
            },
            "Увеличить"
        }
        for id in 0..10 {
            Child {
                signal,
            }
        }
    }
}

#[derive(Props, Clone, PartialEq)]
struct ChildProps {
    signal: Signal<usize>,
}

fn Child(props: ChildProps) -> Element {
    // Этот компонент читает из сигнала, поэтому при изменении сигнала он будет перезапущен
    rsx! {
        "{props.signal}"
    }
}
```

Поскольку подписки происходят при чтении (а не при создании) данных, вы можете передавать сигналы через обычный API контекста:

```rust
fn App() -> Element {
    // Поскольку сигнал никогда не читается в этом компоненте,
    // этот компонент не будет перезапускаться при изменении сигнала
    use_context_provider(|| Signal::new(0));

    rsx! {
        Child {}
    }
}

#[component]
fn Child() -> Element {
    let signal: Signal<i32> = use_context();
    // Этот компонент читает из сигнала, поэтому при изменении сигнала он будет перезапущен
    rsx! {
        "{signal}"
    }
}
```

## Сигналы в Асинхронном Коде

Поскольку сигналы проверяют заимствования во время выполнения, вам нужно быть осторожным при чтении и записи в сигналы внутри асинхронного кода. Если вы удерживаете чтение или запись сигнала через точку await, это чтение или запись может оставаться открытым, пока выполняются другие части вашего приложения:

```rust no_run
async fn double_me_async(value: &mut u32) {
    sleep(100).await;
    *value *= 2;
}
let mut signal = use_signal(|| 0);

use_future(move || async move {
    // Не удерживайте чтения или записи через точки await
    let mut write = signal.write();
    // Пока future ожидает завершения асинхронной работы, запись будет открыта
    double_me_async(&mut write).await;
});

rsx!{
    // Это чтение может вызвать панику, потому что запись всё ещё активна
    "{signal}"
};
```

Вместо удержания чтения или записи через точку await, вы можете клонировать необходимые значения из сигнала, а затем установить результат, когда асинхронная работа завершится:

```rust no_run
async fn double_me_async(value: u32) -> u32 {
    sleep(100).await;
    value * 2
}
let mut signal = use_signal(|| 0);

use_future(move || async move {
    // Клонируем значение из сигнала
    let current_value = signal();
    // Выполняем асинхронную работу
    let new_value = double_me_async(current_value).await;
    // Устанавливаем сигнал в новое значение
    signal.set(new_value);
});

rsx! {
    // Это чтение не вызовет панику, потому что запись никогда не удерживается через точку await
    "{signal}"
};
```

## Жизненный Цикл Сигналов

Сигналы реализованы с помощью [generational-box](https://crates.io/crates/generational-box), что делает все значения Copy, даже если внутреннее значение не реализует Copy.

Это невероятно удобно для разработки UI, но имеет свои компромиссы. Время жизни сигнала привязано к времени жизни компонента, в котором он был создан. Если вы удалите компонент, создавший сигнал, сигнал тоже будет удалён. Вы можете столкнуться с этим, если попытаетесь передать сигнал из дочернего компонента в родительский и удалить дочерний компонент. Чтобы избежать этого, вы можете создать сигнал выше в дереве компонентов, использовать глобальные сигналы или создать сигнал в определённом скоупе с помощью `Signal::new_in_scope`.

**Не передавайте сигналы вверх по дереву компонентов**. Это вызовет проблемы:

```rust
fn MyComponent() -> Element {
    let child_signal = use_signal(|| None);

    rsx! {
        IncrementButton {
            child_signal
        }
    }
}

#[component]
fn IncrementButton(mut child_signal: Signal<Option<Signal<i32>>>) -> Element {
    let signal_owned_by_child = use_signal(|| 0);
    // Не делайте так: это может вызвать проблемы, если дочерний компонент будет удалён
    child_signal.set(Some(signal_owned_by_child));

    todo!()
}
```
