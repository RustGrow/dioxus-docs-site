# Хуки

В Dioxus состояние, локальное для компонента, хранится в *хуках*.

Хуки Dioxus работают аналогично хукам React. Если вы много не занимались веб-разработкой, хуки могут показаться особенно необычными. Хуки предоставляют способ хранения состояния и прикрепления эффектов компонуемости в компонентах. Еще лучше — они менее многословны, чем декларирование структур и реализация трейтов "render"!

## Примитив `use_hook`

Все хуки в Dioxus построены на примитиве `use_hook`. Хотя вы можете никогда напрямую не использовать этот примитив, полезно знать, где в конечном итоге находится все состояние. Примитив `use_hook` — это функция, которая принимает инициализатор и возвращает `.clone()` значения.

```rust
fn Simple() -> Element {
    let count = use_hook(|| 123);
    rsx! { "{count}" }
}
```

Каждый раз, когда вызывается `use_hook`, происходит одно из двух:
- если этот `use_hook` никогда раньше не вызывался, инициализатор запускается и создается новый слот
- в противном случае `use_hook` возвращает клон текущего значения в слоте.

Внутри "hook index" увеличивается на 1 при каждом вызове `use_hook` и сбрасывается в 0 перед перерисовкой компонента.

## Правила хуков

В Dioxus мы прозрачны во внутренней работе фреймворка. Поскольку хуки реализованы путем обхода внутреннего "hook list", у них есть определенные правила, которые приведут к сбою обхода списка и панике вашего приложения. Важно отметить, что эти правила не произвольны — они являются следствием того, как реализованы хуки.

Хуки используют порядок своих вызовов для отслеживания того, какое состояние принадлежит какому хуку. Вы должны вызывать хуки в том же порядке каждый раз, когда запускается компонент. Чтобы порядок был всегда одинаковым, **вы должны вызывать хуки только на верхнем уровне компонента или другого хука**.

Эти правила означают, что есть определенные вещи, которые вы не можете делать с хуками:

### Нет хуков в условиях

Вы не должны вызывать хук-функцию условно. Когда компонент перерисовывается, это может привести к тому, что hook list пропустит запись, заставляя следующий хук получить неправильное значение.

```rust
❌ don't call hooks in conditionals!
// We must ensure that the same hooks will be called every time
// But `if` statements only run if the conditional is true!
// So we might violate rule 2.
    if you_are_happy && you_know_it {
        let something = use_signal(|| "hands");
        println!("clap your {something}")
    }

✅ instead, *always* call use_signal
// You can put other stuff in the conditional though
    let something = use_signal(|| "hands");
    if you_are_happy && you_know_it {
        println!("clap your {something}")
    }
```

### Нет хуков в замыканиях

Аналогично условиям, замыкания предоставляют способ вызова хук-функций в непоследовательном порядке между рендерами. Вместо размещения хука в замыкании предпочтительнее использовать только результат хук-функции в замыкании.

```rust
❌ don't call hooks inside closures!
// We can't guarantee that the closure, if used, will be called in the same order every time
    let _a = || {
        let b = use_signal(|| 0);
        b()
    };

✅ instead, move hook `b` outside
    let b = use_signal(|| 0);
    let _a = || b();
```

### Нет хуков в циклах

Как и условия с замыканиями, вызов хук-функций в циклах может привести к непоследовательному получению значений хуков между рендерами, заставляя хуки возвращать неправильное значение.

```rust
`names` is a Vec<&str>

❌ Do not use hooks in loops!
// In this case, if the length of the Vec changes, we break rule 2
    for _name in &names {
        let is_selected = use_signal(|| false);
        println!("selected: {is_selected}");
    }

✅ Instead, use a hashmap with use_signal
    let selection_map = use_signal(HashMap::<&str, bool>::new);

    for name in &names {
        let is_selected = selection_map.read()[name];
        println!("selected: {is_selected}");
    }
```

### Ранние возвраты

В отличие от React, в Dioxus вы *можете* делать ранний возврат между вызовами хуков. Однако мы обычно не рекомендуем этот паттерн, так как он может привести к аналогичным проблемам согласованности, как и условия. Dioxus поддерживает ранние возвраты, потому что границы ошибок (error boundaries) и границы приостановки (suspense boundaries) используют синтаксис вопросительного знака для эргономики.

```rust
let name = use_signal(|| "bob".to_string());

// ❌ не делайте ранний возврат между хуками!
if name() == "jack" {
    return Err("wrong name".into())
}

let age = use_signal(|| 123);

rsx! { "{name}, {age}" }

// ✅ вместо этого предпочитайте ранний возврат *после* того, как все хуки выполнены
let name = use_signal(|| "bob".to_string());
let age = use_signal(|| 123);

if name() == "jack" {
    return Err("wrong name".into())
}

rsx! { "{name}, {age}" }
```

### Префикс имен хуков с `use_`

По соглашению, хуки — это функции Rust, имеющие префикс `use_`. Когда вы видите функцию с префиксом `use_`, вы должны понимать, что она внутренне обходит hook list компонента и поэтому должна следовать Правилам Хуков.

### Почему хуки должны запускаться в согласованном порядке?

Хуки должны запускаться в согласованном порядке, потому что Dioxus хранит хуки в списке и использует порядок их вызова для определения того, какая часть состояния принадлежит какому хуку.

Давайте рассмотрим пример компонента:

```rust
fn App() -> Element {
    let number = use_signal(|| 1); // Хук 1
    let string = use_signal(|| "hello world".to_string()); // Хук 2
    let doubled = use_memo(move || number() * 2); // Хук 3

    todo!()
}
```

Когда мы впервые создаем компонент, мы запускаем хуки в порядке их определения и сохраняем состояние в компоненте в виде списка.

```rust ignore
[
    Box::new(1),
    Box::new("hello world".to_string()),
    Box::new(2),
]
```

В следующий раз, когда компонент запускается, мы возвращаем элементы из списка состояний вместо создания нового состояния.

```rust ignore
[
    Box::new(1), // Хук 1 возвращает 1
    Box::new("hello world".to_string()), // Хук 2 возвращает "hello world"
    Box::new(2), // Хук 3 возвращает 2
]
```

Порядок запуска хуков должен быть одинаковым, потому что порядок определяет, какой хук получает какое состояние! Если вы запустите хуки в другом порядке, Dioxus может запаниковать, потому что не сможет преобразовать состояние обратно в правильный тип, или вы можете просто получить неправильное состояние для вашего хука.

## Популярные хуки

Dioxus предоставляет множество встроенных хуков:

- `use_signal` — создает реактивный сигнал
- `use_memo` — создает мемоизированное вычисление
- `use_effect` — запускает побочный эффект
- `use_resource` — управляет асинхронными данными
- `use_context` — читает контекст из дерева компонентов
- `use_context_provider` — предоставляет контекст дочерним компонентам

## Кастомные хуки

Вы можете создавать свои собственные хуки, комбинируя существующие:

```rust
fn use_counter(initial: i32) -> (Signal<i32>, Callback<()>, Callback<()>) {
    let mut count = use_signal(|| initial);
    let increment = use_callback(move |()| count += 1);
    let decrement = use_callback(move |()| count -= 1);
    (count, increment, decrement)
}
```
