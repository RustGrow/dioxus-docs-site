# Обход RSX

Хотя RSX чрезвычайно способен, *некоторые* изменения UI требуют низкоуровневого доступа к системным виджетам или императивного подхода программирования. Dioxus предоставляет ряд "обходных путей", позволяя использовать альтернативные UI-техники, которые не вписываются в декларативную парадигму RSX. Также Dioxus относительно молод и может не поддерживать *каждую* функцию, которую имеет платформо-специфический рендерер.

## Пользовательские атрибуты элементов

Под капотом Dioxus объявляет каждый атрибут элемента как набор констант, описывающих статические свойства атрибута. Определение примерно эквивалентно этому псевдокоду:

```rust
struct video;
impl video {
    const src: AttributeDefinition = AttributeDefinition {
        name: "src",
        namespace: None,
        type: String
    };
    const autoplay: AttributeDefinition = AttributeDefinition {
        name: "controls",
        namespace: None,
        type: Boolean
    };
}

//
rsx! {
    video { src: "...", autoplay: true }
}
```

В некоторых случаях объявление атрибута может отсутствовать, или вам нужно использовать пользовательское имя. RSX позволяет это с помощью имён атрибутов, заключённых в кавычки. Просто оберните имя пользовательского атрибута в кавычки и передайте любое выражение, которое оценивается в `IntoAttributeValue`:

```rust
rsx! {
    div {
        "data-my-button-id": 123
    }
}
```

Пользовательские атрибуты могут быть чрезвычайно удобны при использовании data-атрибутов и пользовательских CSS-селекторов.

## Dangerous Inner HTML

Если вы работаете с предварительно отрендеренными ресурсами, выводом из шаблонов или выводом из JS-библиотеки, то, возможно, захотите передать HTML напрямую, минуя Dioxus. В таких случаях используйте `dangerous_inner_html`. Этот атрибут устанавливает HTML-поле `textContent` элемента в предоставленное значение. Это перезапишет любые другие атрибуты или дочерние элементы элемента.

Например, поставка конвертера markdown-в-Dioxus может значительно раздуть размер конечного приложения. Вместо этого лучше предварительно отрендерить markdown в HTML, а затем включить HTML напрямую в вывод. Мы используем этот подход для [домашней страницы Dioxus](https://dioxuslabs.com):

```rust
// this should come from a trusted source
    let contents = "live <b>dangerously</b>";

    rsx! {
        div { dangerous_inner_html: "{contents}" }
    }
```

> Внимание! Этот атрибут называется "dangerous_inner_html", потому что передавать ему данные, которым вы не доверяете, **опасно**. Если не быть осторожным, можно легко подвергнуть пользователей атакам [межсайтового скриптинга (XSS)](https://en.wikipedia.org/wiki/Cross-site_scripting).
>
> Если вы работаете с ненадёжным вводом, обязательно санитизируйте HTML перед передачей его в `dangerous_inner_html` — или просто передайте его в текстовый элемент, чтобы экранировать любые HTML-теги.

## Веб-компоненты

Хотя мы обычно предлагаем создавать новые компоненты непосредственно в Dioxus, сторонний компонент может распространяться как [*Web Component*](https://www.webcomponents.org). Веб-компоненты предоставляют фреймворко-независимый способ создания и распространения пользовательских HTML-элементов.

Любой элемент с дефисом в имени является веб-компонентом. Веб-компоненты отображаются в Dioxus напрямую без проверки типов. Обычно вы будете импортировать веб-компонент *в* Dioxus. Поэтому мы рекомендуем оборачивать веб-компоненты в типобезопасный компонент, чтобы облегчить их использование.

```rust
rsx! {
        my-web-component {}
    }
```

Поскольку веб-компоненты нетипизированы, у них нет атрибутов по умолчанию. Каждое имя атрибута должно быть заключено в кавычки, поэтому мы предлагаем обернуть веб-компонент в компонент Dioxus:
```rust
// наш dioxus-компонент предоставляет строго типизированную обёртку вокруг нашего строкового веб-компонента
#[component]
fn MyWebComponent(name: String, age: i32) -> Element {
    rsx! {
        my-web-component {
            "name": "hello, {name}",
            // "age": age + 10
        }
    }
}
```

## Прямой доступ к DOM

Как упоминалось ранее, RSX — *декларативный.* Вы компонуете элементы в блоке `rsx! {}`, и Dioxus выполняет рендеринг. Иногда требуется низкоуровневый доступ к DOM-элементам для создания глубоко интерактивного UI. Это может включать рендеринг в canvas-элемент или выполнение синхронной модификации свойств элемента.

Для получения прямого доступа к базовому [HTML DOM](https://developer.mozilla.org/en-US/docs/Web/API/Document_Object_Model/Introduction), Dioxus предоставляет несколько встроенных механизмов:

- Выполнение JavaScript через `eval`
- Использование [`web-sys`](https://docs.rs/web-sys/latest/web_sys/) для получения элемента по ID
- Использование обработчика события `onmounted`
- Использование событий `onresize` и `onvisible`

### Eval

Dioxus предоставляет функцию `eval`, которая позволяет выполнять произвольный JavaScript в платформо-специфическом рендерере. В вебе это использует [`web-sys`](https://docs.rs/web-sys/latest/web_sys/), а для webview-рендерера — нативный метод `eval` webview.

Можно выполнить любой валидный JavaScript. Dioxus преобразует исходный код во входное объявление `Function`, а затем позволяет захватить его результат. Чтобы отправить пользовательские данные в JavaScript, мы просто форматируем исходный код. Чтобы вернуть данные из JavaScript, используем `dioxus.send()` и метод `.recv()` eval:

```rust
use dioxus::prelude::*;

fn app() -> Element {
    rsx! {
        button {
            onclick: move |_| async move {
                // Можно отправлять значения из Rust в JavaScript-код с помощью метода `send` объекта, возвращённого `eval`.
                let mut eval = document::eval(
                    r#"for(let i = 0; i < 10; i++) {
                        // Можно асинхронно отправлять значения с помощью метода `dioxus.send()`.
                        dioxus.send(i);
                    }"#
                );

                // Можно получать значения из JavaScript-кода с помощью метода `recv` объекта, возвращённого `eval`.
                for _ in 0..10 {
                    let value: i32 = eval.recv().await.unwrap();
                    println!("Received {}", value);
                }
            },
            "Log Count"
        }
    }
}
```

### Использование `web-sys` и downcasting событий

В вебе возможно использовать крейт [`web-sys`](https://docs.rs/web-sys/latest/web_sys/) для прямого вызова JavaScript-методов из Rust. Это использует foreign-function-interfaces для моста между Rust и JavaScript. Мы не обязательно рекомендуем использовать web-sys во *всех* случаях, так как web-sys в настоящее время не портируется на рендереры Dioxus Desktop и Mobile.

С помощью web-sys можно вызывать большинство JavaScript-методов со строго типизированным Rust-интерфейсом:

```rust
rsx! {
    let alert_it = move |_| {
        let window = web_sys::window().unwrap();
        window.alert_with_message("Hello from Rust!");
    };
    button { onclick: alert_it, "Click to alert" }
}
```

Если вам *нужно* использовать web-sys на desktop и mobile, возможно, стоит рассмотреть [Dioxus с Tauri](#using-dioxus-in-tauri).

### Использование `getElementById`

При использовании eval или web_sys может быть полезно получить прямую ссылку на HTML DOM-узел. Обычно мы предлагаем создать ID для заданного элемента, а затем использовать `getElementById` для ссылки на этот узел позже.

```rust
// Установка уникального ID для div
let id = use_hook(|| Uuid::new_v4());

// Ссылка на него в нашей eval-логике
let set_div_contents = move |_| async move {
    dioxus::document::eval(format!(r#" document.getElementById("{{div-{id}}}").innerText = "one-two-three" "#)).await;
};

rsx! {
    // А затем назначить его на самом элементе
    div { id: "div-{id}" }
    button { onclick:  set_div_contents, "Set Div Directly" }
}
```

## Дочерние окна и оверлеи

Некоторым приложениям требуется низкоуровневый доступ к HTML-элементу [`canvas`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/canvas). Например, CAD-приложения, видеоигры, фоторедакторы, видеоредакторы или всё, что полагается на большое количество мультимедиа, может захотеть вручную рендерить GUI-текстуры.

При использовании webview-рендерера можно наложить ваш Dioxus HTML-контент *поверх* нативной текстуры. Это продвинутый обходной путь, открывающий весь конвейер рендеринга — чрезвычайно мощный, но также довольно сложный.

## Использование Dioxus в Tauri

Если вам *нужно* использовать крейт `web-sys` на desktop и mobile платформах, то [Tauri](https://tauri.app) может быть полезен. Tauri — фреймворк, позволяющий комбинировать пользовательский фронтенд через IPC-границу с Rust-кодом, работающим нативно. Это несколько похоже на Dioxus, но вместо того, чтобы ваш UI-код работал нативно, он работает как WebAssembly *внутри* webview. Это может быть медленнее и сложнее в настройке, но позволяет прямой доступ к DOM на всех платформах.

Dioxus-Web поддерживается как опция фронтенда при создании нового Tauri-приложения, так что обязательно загляните в [их документацию](https://tauri.app/start/).

## Нативные виджеты

Официальные рендереры Dioxus в настоящее время отображают только HTML и CSS. Это делается либо через `HTMLDomElement` с `web-sys`, либо через eval для webview-рендереров. Иногда требуется отобразить платформо-нативный виджет. Внутренне Dioxus использует это для открытия диалогов выбора файлов, выбора цвета и обеспечения функциональности, где важна платформенная согласованность.

![File Upload Dialog](/assets/07/file-upload.png)

Это довольно продвинуто и требует использования FFI в Objective-C и Kotlin для работы с системными библиотеками. Подробнее см. в [документации dioxus-desktop](https://crates.io/crates/dioxus-desktop).

## Dioxus Native

Для *полного* контроля над DOM мы построили рендерер *Dioxus Native*. Этот рендерер комбинирует платформо-нативные виджеты вместе с урезанным HTML/CSS-рендерером для отрисовки дерева виджетов Dioxus прямо на экране. В настоящее время Dioxus Native поддерживает различные бэкенды на основе крейта [Vello](https://github.com/linebender/vello).

Dioxus Native находится в зачаточном состоянии. Мы специально построили Dioxus Native для отрисовки произвольных GPU-текстур в canvas-элементы. Вместо использования дочерних окон и оверлеев можно напрямую передавать WGPU-текстуры в HTML-элементы. Аналогично, можно встраивать Dioxus в любое существующее WGPU-приложение, например, игру на Bevy.
