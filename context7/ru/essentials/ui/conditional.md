# Условный рендеринг

Наши пользовательские интерфейсы пока что были довольно статичными. Однако большинство приложений, которые мы строим с Dioxus, обычно содержат много динамического контента. Наши интерфейсы будут реагировать на изменения кнопок, полей ввода, слайдеров или внешних источников данных, таких как сеть. Приложения Dioxus обычно хранят это динамическое состояние в хуках (Hooks) или контексте (Context).

В этой главе мы не будем слишком глубоко погружаться в то, как хранить состояние — будущие главы подробно рассматривают состояние.

## Выражения

Как и JSX, RSX позволяет легко компоновать объекты `Element` вместе с помощью обычного Rust-кода. Вы можете писать Rust-выражения прямо внутри вашего RSX. Пока выражение возвращает `Element` или что-либо, реализующее `IntoDynNode`, можно просто обернуть его в фигурные скобки (`{}`):

```rust
let content = "world!";
rsx! {
    h1 {
        "Hello"
        {content}
    }
}
```

Например, может потребоваться создать строку из некоторых сложных функций форматирования:

```rust
rsx! {
    span {
        {
            format!(
                "The time is: {now}, your timezone is {zone}",
                now = current_time(),
                zone = current_timezone()
            ).to_ascii_uppercase()
        }
    }
}
```

Или мы можем захотеть динамически отрендерить некоторый RSX и присвоить его переменной:

```rust
let header = match current_timezone() {
    TimeZone::PST => rsx! {
        h1 { "Welcome home" }
    },
    _ => rsx! {
        h1 { "Bon voyage!" }
    },
}

rsx! {
    div {
        {header}
    }
}
```

Система выражений Rust делает вычисление RSX из выражений `match` и блоков `if` довольно удобным. В то время как в JavaScript вы могли бы использовать тернарный оператор:

```jsx
let screen = authenticated ? renderApp() : renderLogin();

return <div>{screen}</div>;
```

В Dioxus вы просто используете оператор if/else:

```rust
let screen = if authenticated { render_app() } else { render_login() };
rsx! {
    div {
        {screen}
    }
}
```

Гварды Rust могут быть особенно полезны в таких сценариях, позволяя выбирать варианты match с помощью встроенных выражений `if`.

```rust
let header = match current_timezone() {
    TimeZone::PST => rsx! {
        h1 { "Welcome home" }
    },
    _ if app.snoozed() => rsx! {
        h1 { "snoozed..." }
    },
    _ => rsx! {
        h1 { "Bon voyage!" }
    },
}

rsx! {
    div {
        {header}
    }
}
```

## Трейт IntoDynNode

Dioxus использует трейт [`IntoDynNode`](https://docs.rs/dioxus-core/latest/dioxus_core/trait.IntoDynNode.html) для определения, может ли выражение использоваться внутри RSX. Преобразование примет Rust-выражение и превратит его в один из четырёх вариантов `DynamicNode`:

- Компонент: Функции, принимающие Properties и отображающие Element
- Текст: Rust-тип `String`
- Плейсхолдер: Оптимизированное значение `None`
- Список: Вектор элементов

Многие типы реализуют этот трейт. Например, пустые выражения допустимы:
```rust
rsx! {
    div {
        { /* empty.. */}
    }
}
```

Другие объекты Element допустимы:

```rust
let inner = rsx! { "inner" };
rsx! {
    div {
        {inner}
    }
}
```

Все строковые типы (str, String, Arguments) допустимы:
```rust
rsx! {
    div {
        // Строки
        {"abc"}

        // ленивое форматирование
        {format_args!("lazy fmt -> {}", arg())}
    }
}
```

Rust-тип `Option` допустим при условии, что внутренний тип реализует `IntoDynNode`:

```rust
let inner = Some(rsx! { "inner" });
rsx! {
    div {
        {inner}
    }
}
```

И даже итераторы могут стать VNode через вариант List:

```rust
let cards = (0..10).map(|i| rsx! {
    li { "Card: {i}" }
});

rsx! {
    ol {
        {cards}
    }
}
```

Итераторы очень интересны, поскольку IntoDynNode реализован для всего, что является итератором. Например, мы могли бы построить пользовательский итератор, возвращающий `Element`.

```rust
let mut count = 0;
let cards = std::iter::from_fn(move || {
    count += 1;
    if count > 6 {
        return None;
    }

    Some(rsx! { "card {count}" })
})

rsx! {
    ol {
        {cards}
    }
}
```

## Встроенные операторы `If`

При рендеринге контента, основанного на логическом условии (например, "активен" или "неактивен"), RSX предоставляет небольшой "синтаксический сахар", позволяющий использовать встроенные операторы `if` в RSX.

```rust
let logged_in = use_signal(|| false);

    rsx! {
        div {
            if logged_in() {
                "You are logged in"
            } else {
                "You are not logged in"
            }
        }
    }
```

Обратите внимание, что тело встроенных операторов `if` *является* RSX, а не Rust-выражениями. Этот синтаксический сахар помогает сохранять блоки RSX аккуратными и идиоматичными.
```rust
rsx! {
    div {
        if logged_in() {
            LoggedInScreen {}
        } else {
            LoggedOutScreen {}
        }
    }
}
```

Встроенные операторы `if` отличаются от Rust одним образом: они всё равно возвращают `Element`, даже без ветки `else`. Если RSX не находит ветку `else` в вашем операторе `if`, он автоматически возвращает элемент-плейсхолдер.

```rust
rsx! {
    div {
        if logged_out() {
            span { "You should log in!" }
        }
    }
}
```

## Ещё синтаксический сахар?

Синтаксис может быть очень субъективным, и синтаксический сахар, такой как встроенные `if` и `for`, может открыть дверь к непоследовательному поведению. Мы не планируем вводить какой-либо дополнительный синтаксический сахар в RSX. Наша цель — поддерживать сходство с JSX от React, слегка адаптируя эргономику для Rust-разработчиков.

Синтаксис RSX был тщательно разработан для хорошей работы с вашим обычным процессом разработки:

- Набор элемента RSX включает ввод имени, а затем одной фигурной скобки
- RSX не требует дополнительных расширений редактора для отличной поддержки
- RSX следует токенизации Rust для автоматической подсветки и сворачивания кода

Определённо, потратьте некоторое время на изучение RSX, чтобы почувствовать его.
