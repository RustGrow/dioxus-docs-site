# Справочник по горячей перезагрузке в Dioxus

Движок горячей перезагрузки Dioxus невероятно мощный. При правильном использовании он обеспечивает самый быстрый процесс разработки для создания приложений на Rust.

> Dioxus 0.5 имел ограниченную форму горячей перезагрузки, а Dioxus 0.6 значительно улучшил её.
>
> **Dioxus 0.7 представляет экспериментальную горячую перезагрузку Rust**, став первым Rust-фреймворком, поддерживающим горячую перезагрузку настоящего Rust-кода. 🎉🎉

## Горячая перезагрузка RSX

Горячая перезагрузка RSX — фундаментальная часть опыта разработки в Dioxus. Она позволяет изменять структуру, стили и содержимое пользовательского интерфейса без перекомпиляции всего приложения.

Горячая перезагрузка RSX позволяет мгновенно добавлять, удалять или изменять элементы в блоке `rsx!`. Парсер RSX работает как во время компиляции, так и в наших devtools, позволяя DX полностью обходить перекомпиляцию вашего Rust-кода.

```rust
fn App() -> Element {
    rsx! {
        // Можно добавлять, удалять или изменять любые элементы
        div { class: "container" }
        h1 { "My App" }
        button { "Click me" }
    }
}
```

Все строковые атрибуты поддерживают мгновенную горячую перезагрузку:
```rust
fn Button() -> Element {
    rsx! {
        button {
            // Все эти можно мгновенно перезагрузить
            class: "btn btn-primary",
            id: "my-button",
            title: "Click this button",
            style: "background: blue; color: white;",

            "Submit"
        }
    }
}
```

Горячая перезагрузка поддерживает изменение сложных форматированных строк в любом месте вашего RSX. Хотя вы не можете мгновенно перезагружать внутренние Rust-выражения, вы *можете* перемещать существующие выражения между форматированными строками.

```rust
fn Counter() -> Element {
    let count = use_signal(|| 0);

    rsx! {
        div {
            // Мы можем переместить эту переменную `count` отсюда
            "Count: {count}"

            button {
                ... сюда, без перекомпиляции!
                "Increment ({count})"
            }
        }
    }
}
```

Можно горячо перезагружать простые Rust-выражения, переданные как props компонентов. Если значение атрибута является [Rust "литералом"](https://doc.rust-lang.org/reference/expressions/literal-expr.html) — одиночным "токеном", например числом, булевым значением или строкой — DX перезагрузит его, перепарсив новый атрибут и модифицировав props компонента на месте.

```rust
fn App() -> Element {
    rsx! {
        MyButton {
            text: "Click me", // попробуйте изменить текст
            enabled: true, // попробуйте изменить true на false!
            count: 123, // или изменить числовое значение!
        }
    }
}

#[component]
fn MyButton(text: String, enabled: bool, count: i32, color: String) -> Element {
    rsx! {
        button { disabled: !enabled, "{text} - {count}" }
    }
}
```

Горячая перезагрузка работает внутри условных блоков, циклов и дочерних элементов компонентов. Обратите внимание, что внутренние *выражения* не поддерживают мгновенную горячую перезагрузку RSX, но внутренние *элементы* и *разметка* поддерживают.

```rust
fn TodoList() -> Element {
    let todos = use_signal(|| vec!["Learn Dioxus", "Build an app"]);

    rsx! {
        ul {
            // Мы можем изменить *тело*
            for (i, todo) in todos().iter().enumerate() {
                li {
                    key: "{i}",
                    class: "todo-item",
                    "{todo}"
                }
            }
        }

        // Тела условных блоков тоже поддерживают горячую перезагрузку
        if todos().len() > 5 {
            div { class: "warning", "You have many todos!" }
        }
    }
}
```

## Что требует полной пересборки (или хот-патча!)

Хотя горячая перезагрузка RSX очень способна, некоторые изменения всё ещё требуют полной пересборки приложения:

- **Новые переменные или выражения**, отсутствующие в последней компиляции.
- **Изменения логики** вне RSX (тела функций, хуки и т.д.).
- **Сигнатуры компонентов** (добавление/удаление props).
- **Операторы импорта** и структура модулей.
- **Сложные Rust-выражения** в атрибутах, включающие вызовы функций.

Когда горячий патчинг Rust включён с флагом `--hotpatch`, DX модифицирует ассемблер вашего приложения *на месте* и не требует полной пересборки. С включённым хот-патчингом DX редко инициирует полные пересборки. В любой момент можно вручную принудить полную пересборку приложения, нажав клавишу `r` с открытым DX TUI.

## Экспериментальное: горячий патчинг Rust

**Новое в Dioxus 0.7**, вы можете включить экспериментальную горячую перезагрузку Rust-кода с помощью флага `--hotpatch`. Эта функция революционна — позволяет изменять Rust-логику и видеть изменения без пересборки.

Для использования горячей перезагрузки Rust запустите `dx serve --hotpatch`. Дополнительный флаг требуется, пока хот-патчинг находится в экспериментальном режиме, хотя мы планируем сделать его поведением по умолчанию в будущем.

```bash
dx serve --hotpatch
```

Эта система, названная **Subsecond**, может перезагружать большинство изменений в Rust-коде. Однако есть несколько ограничений:

- Вы можете добавлять новые глобальные переменные во время выполнения, но их деструкторы никогда не будут вызваны.
- Глобальные переменные отслеживаются между патчами, но переименования наблюдаются как введение новой глобальной переменной.
- Изменения статических инициализаторов не будут наблюдаться.

Также, что важнее всего, горячий патчинг Rust в настоящее время отслеживает только "верхний" крейт в вашем проекте. Если вы редактируете код в какой-либо из ваших зависимостей — что может быть *вашим* крейтом в workspace — DX *не* регистрирует это изменение. В то время как горячая перезагрузка RSX работает через весь workspace, Subsecond в настоящее время — нет.

Subsecond также работает вне Dioxus. Многие проекты уже приняли библиотеку Subsecond для горячей перезагрузки Rust. Например, Bevy и Iced уже имеют интеграции с Subsecond:

### Обзор API Subsecond

Subsecond — это самостоятельная библиотека горячей перезагрузки для Rust. Она предоставляет простой API для создания любой функции с поддержкой горячей перезагрузки.

Для авторов библиотек можно использовать "горячие" функции с `subsecond::current`:

```rust
/// Пользовательская функция tick / launch / start
pub fn tick(handler: Fn(Request) -> Response) {
    // Создаем "горячую" функцию, которую можно инспектировать
    let hot_fn = subsecond::current(handler);

    // Проверяем, была ли эта функция пропатчена
    if hot_fn.changed() {
        // делаем что-то
    }

    // Регистрируем обработчик, который будет вызван при патче функции
    hot_fn.on_changed(|| /* делаем что-то */);

    // Вызываем горячую функцию
    hot_fn.call((request))
}
```

Для авторов приложений можно использовать `subsecond::call()`, чтобы сделать функцию с поддержкой горячей перезагрузки:

```rust
fn handle_request(request: Request) -> Response {
    subsecond::call(|| {
        // делаем что-то...
    })
}
```

Если горячая функция активно вызывается, Subsecond отмотает стек до "наиболее чистой" точки входа. Например, сервер с горячей перезагрузкой будет иметь две "горячие" точки: в начале сервера и в начале обработчика запросов. Когда сервер перезагружается, Subsecond отматывает стек до первой горячей точки, а затем вызывает функцию снова.

```rust
// Изменения в `serve` перезагрузят сервер
fn serve() {
    let router = Router::new();
    router.get("/", handle_request);
    router.serve("0.0.0.0:8080");
}

// Изменения ниже "handle_request" не перезагрузят роутер
fn handle_request(request: Request) -> Response {
    // делаем что-то
}
```

Авторы фреймворков могут чередовать свои собственные точки входа горячей перезагрузки с пользовательским кодом. Это позволяет добавлять новые якоря в долго выполняющийся stateful код:

```rust
fn main() {
    // serve является "горячей" и перестроит роутер, если изменится
    webserver::serve("0.0.0.0:8080", || {
        Router::new()
            // get является "горячей", и изменения в handle_request не перестроят роутер
            .get("/", |req| Response::websocket(handle_socket))
    })
}

fn handle_socket(ws: &WebSocket) {
    subsecond::call(|| {
        // делаем что-то с websocket
    })
}
```

## Горячая перезагрузка ресурсов

Горячая перезагрузка ресурсов позволяет изменять CSS, изображения и другие статические файлы без пересборки приложения. Это работает без проблем с системой макроса `asset!()`.

### Горячая перезагрузка CSS

CSS-файлы автоматически отслеживаются и горячо перезагружаются при изменении:

```rust
fn App() -> Element {
    rsx! {
        // Редактирование этой таблицы стилей вызовет мгновенные обновления в работающем приложении
        Stylesheet { href: asset!("/assets/main.css") }
        div { class: "my-component", "Hello World!" }
    }
}
```

```css
/* В assets/main.css — изменения здесь применяются мгновенно */
.my-component {
    background: blue;
    color: white;
    padding: 20px;
    /* Измените это на red и увидите мгновенные обновления! */
}
```

SCSS-файлы автоматически перекомпилируются при изменениях, и сгенерированный CSS будет горячо перезагружён.

### Горячая перезагрузка изображений и статических ресурсов

Статические ресурсы, такие как изображения, также поддерживают горячую перезагрузку:

```rust
fn Header() -> Element {
    rsx! {
        img { src: asset!("/assets/logo.png") }
    }
}
```

Когда вы редактируете `/assets/logo.png`, изменение мгновенно отображается в работающем приложении.

### Интеграция с Tailwind CSS

Когда вы запускаете `serve` приложения, DX автоматически загружает и запускает Tailwind CLI в фоновом режиме. Если в корне проекта обнаружен файл `tailwind.css`, наблюдатель Tailwind будет следить за вашим Rust-кодом на изменения, а затем перекомпилировать выходной файл `/assets/tailwind.css`.

<video src="/assets/07/tailwind-inline.mp4" controls></video>

Вы можете вручную настроить входные и выходные расположения файлов Tailwind, используя поля конфигурации `tailwind_input` и `tailwind_output` в Dioxus.toml вашего проекта.
