# Атрибуты

Хотя мы можем собирать интерфейс из нестилизованных элементов и текста, обычно мы хотим настроить их внешний вид и поведение. Здесь нам пригодятся *атрибуты элементов*. Атрибуты предоставляют рендереру дополнительную информацию о том, как отображать интерфейс.

Атрибуты можно задавать, добавляя имя атрибута, двоеточие и значение в тело элемента. Например, мы можем захотеть стилизовать div определённым [классом](https://www.w3schools.com/html/html_classes.asp) и [ID](https://www.w3schools.com/html/html_id.asp), которые добавляются как атрибуты:

```rust
rsx! {
    div {
        class: "container",
        id: "root-container"
    }
}
```

Мы можем использовать атрибут для установки `type` элемента input. По умолчанию тип — `text`, который отображает текстовое поле ввода, но можно установить его в `number`, чтобы принимать только числа:

```rust
rsx! {
        input { type: "number" }
    }
```

Как и текстовые узлы, атрибуты могут содержать форматированные сегменты. Мы можем установить значение элемента input в сигнал для его контроля:

```rust
let mut value = use_signal(|| "Hello world".to_string());
    rsx! {
        input { value: "{value}" }
    }
```

## Область действия атрибутов

У каждого элемента есть два набора атрибутов:

- [Глобальные атрибуты](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes): атрибуты, которые можно применить к *любому* элементу
- [Специфические атрибуты](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes): атрибуты, которые применяются только к одному конкретному элементу

Например, все элементы поддерживают атрибуты `id` и `class`, но только элементы `video` поддерживают атрибут `autoplay`. Полный список атрибутов можно найти по ссылкам выше.

## Нетекстовые атрибуты

Обычно атрибуты добавляются к элементам с использованием форматированного текста. Однако атрибуты могут принимать широкий диапазон типов значений, включая:

- `Text`: Форматированный текст, тип `String` или всё, что реализует `Display`.
- `Float`: Числа с плавающей точкой, обычно для слайдеров и полей ввода.
- `Int`: Целые числа для дискретных градаций.
- `Bool`: Логическое значение, указывающее истину/ложь.
- `Listener`: Rust-колбэк, который будет выполнен при срабатывании атрибута.
- `Any`: Тип-стёртый [`Rc<dyn Any>`](https://doc.rust-lang.org/std/any/index.html), обычно используемый сторонними рендерерами.
- `None`: Атрибут будет полностью удалён из элемента.

Чаще всего вы будете использовать атрибут `bool` для установки логического состояния:

```rust
rsx! {
    input {
        type: "checkbox",
        checked: true
    }
}
```

Или вариант `Some`/`None` для установки HTML Boolean Attribute:
```rust
rsx! {
    div { itemscope: Some("scope") }
}
```

Обратите внимание, что Dioxus автоматически преобразует `false` для некоторых атрибутов в `None`, чтобы соответствовать поведению [HTML Boolean Attribute](https://developer.mozilla.org/en-US/docs/Glossary/Boolean/HTML).

## Обработчики событий

В то время как некоторые атрибуты влияют на то, как элемент отображается, другие атрибуты влияют на его интерактивное поведение. Эти атрибуты, называемые обработчиками событий (Event Listeners), позволяют реагировать на действия пользователя.

В RSX обработчики событий всегда начинаются с `on`. Синтаксис такой же, как у обычных атрибутов, но обработчики событий принимают только замыкание, которое реагирует на событие. Мы можем прикрепить обработчик события к событию `oninput` элемента input, чтобы слушать изменения ввода:

```rust
rsx! {
        input {
            oninput: move |event| {
                println!("Input changed to: {}", event.value());
            },
        }
    }
```

Больше информации об обработчиках событий, включая то, как события всплывают и как предотвратить поведение по умолчанию, можно найти позже в разделе [Обработчики событий](../basics/event-handlers.md) части про реактивность.

Доступен широкий спектр обработчиков событий — подробнее см. полный [HTML-список](https://developer.mozilla.org/en-US/docs/Web/Events).

## Распространение атрибутов

Иногда набор атрибутов, которые вы хотите передать элементу, может быть динамическим или определённым в другом месте приложения. В таких случаях можно распространить списки атрибутов в элементы с помощью синтаксиса `..`. Обычно списки атрибутов передаются в компонент через его свойства (Properties), что мы рассмотрим в следующей главе.

```rust
let attributes = vec![
    Attribute {
        name: "id",
        namespace: None,
        volatile: false,
        value: "cool-button".into_value(),
    }
];

rsx! {
    button { ..attributes, "button" }
}
```

Списки атрибутов будут объединены в порядке их появления, поэтому более поздние атрибуты в списке имеют приоритет над более ранними. Распространение атрибутов становится очень полезным при рефакторинге интерфейса в библиотеку переиспользуемых компонентов.

## Специальные атрибуты

Большинство атрибутов в RSX отображаются дословно, но есть несколько исключений. В некоторых случаях RSX отклоняется от традиционного HTML, чтобы упростить разработку или лучше работать с инструментами экосистемы.

### Условные атрибуты

Условно установить атрибут можно, присвоив значению атрибута незавершённое выражение if. Если выражение if истинно, атрибут будет установлен:

```rust
let number_type = use_signal(|| false);
    rsx! {
        input { type: if number_type() { "number" } }
    }
```

### Атрибуты стилей

Помимо стандартного атрибута `style`, каждый стиль также можно передать как отдельный атрибут. Например, мы можем установить `color` и `font-size` элемента, используя атрибуты `color` и `font_size`:

```rust
rsx! {
        div { style: "width: 20px; height: 20px; background-color: red; margin: 10px;" }
        div {
            width: "20px",
            height: "20px",
            background_color: "red",
            margin: "10px",
        }
    }
```

### Атрибут class

Большинство атрибутов можно определить только один раз для элемента, но атрибут `class` можно определять несколько раз. Каждый класс будет добавлен в список классов элемента. Это удобно при добавлении множества опциональных классов к элементу в системе стилизации, например, TailwindCSS:

```rust
rsx! {
        span {
            class: if red { "bg-red-500" },
            class: if blue_border { "border border-blue-500" },
            class: "w-4 h-4 block",
        }
    }
```

Эта функция особенно важна при использовании TailwindCSS, так как компилятор классов не понимает форматированные Rust-строки при сборке классов. Размещая динамический класс в соседнем атрибуте, компилятор Tailwind видит *оба* списка классов во время компиляции.

### onresize и onvisible

Dioxus предоставляет два пользовательских HTML-атрибута, *не* найденных в спецификации HTML.

- onresize
- onvisible

Dioxus автоматически создаёт кроссплатформенный `IntersectionObserver`, который генерирует соответствующие события.

С помощью onresize можно отслеживать изменения размера и позиции элемента:

```rust
fn app() -> Element {
    let mut items = use_signal(|| 100);

    rsx! {
        // Добавление значения приведёт к повторному рендерингу div с дополнительным div
        button { onclick: move |_| items += 1, "Add one" }

        div {
            // Это будет вызвано при изменении размера div
            onresize: move |data| {
                info!("resized to {:#?}", data.get_border_box_size().unwrap());
            },

            for x in 0..items() {
                div { "{x}" }
            }
        }
    }
}
```

С помощью `onvisible` можно обрабатывать случаи, когда элемент входит и выходит из области видимости. Это полезно для реализации ленивой загрузки, бесконечного скролла и виртуальных списков:

```rust
fn app() -> Element {
    rsx! {
        div {
            onvisible: move |data| info!("visibility changed"),
            "Hello world!"
        }
    }
}
```

Можно добавлять в приложение сложные анимации с учётом скролла, не нуждаясь в написании пользовательского JavaScript.

### Пользовательские атрибуты

Dioxus имеет предварительно настроенный набор атрибутов, которые проверяются во время компиляции. Если заключить имя атрибута в кавычки, можно использовать пользовательский атрибут вне предопределённого набора:

```rust
rsx! {
        div { "style": "width: 20px; height: 20px; background-color: red;" }
    }
```

Обратите внимание, что это работает даже с обработчиками событий. Мы иногда используем это для вставки небольших фрагментов JavaScript в наши приложения, когда написание соответствующего кода web-sys может быть слишком многословным:

```rust
rsx! {
    button {
        "onclick": "navigator.clipboard.writeText(window.document.title);",
        "Copy to clipboard"
    }
}
```

### Обходной путь через HTML

Если вы работаете с предварительно отрендеренными ресурсами, выводом из шаблонов или выводом из JS-библиотеки, то, возможно, захотите передать HTML напрямую, минуя Dioxus. В таких случаях используйте `dangerous_inner_html`.

`dangerous_inner_html` устанавливает текстовое содержимое элемента в предоставленное значение. Это перезапишет любые другие атрибуты или дочерние элементы элемента.

Например, поставка конвертера markdown-в-Dioxus может значительно раздуть размер конечного приложения. Вместо этого лучше предварительно отрендерить markdown в HTML, а затем включить HTML напрямую в вывод. Мы используем этот подход для [домашней страницы Dioxus](https://dioxuslabs.com):

```rust
// this should come from a trusted source
    let contents = "live <b>dangerously</b>";

    rsx! {
        div { dangerous_inner_html: "{contents}" }
    }
```

> Внимание! Этот атрибут называется "dangerous_inner_html", потому что передавать ему данные, которым вы не доверяете, **опасно**. Если не быть осторожным, можно легко подвергнуть пользователей атакам [межсайтового скриптинга (XSS)](https://en.wikipedia.org/wiki/Cross-site_scripting).
>
> Если вы работаете с ненадёжным вводом, обязательно санитизируйте HTML перед передачей его в `dangerous_inner_html` — или просто передайте его в текстовый элемент, чтобы экранировать любые HTML-теги.
