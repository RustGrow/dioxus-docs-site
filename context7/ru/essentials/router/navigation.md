# Ссылки и навигация

Когда мы разбиваем наше приложение на страницы, нам нужно предоставить пользователям способ перемещаться между ними. На обычных веб-страницах для этого мы бы использовали элемент привязки (anchor), например так:

```html
<a href="/other">Ссылка на другую страницу</a>
```

Однако мы не можем делать это при использовании маршрутизатора по трём причинам:

1. Теги привязки заставляют браузер загружать новую страницу с сервера. Это занимает много времени, и гораздо быстрее позволить маршрутизатору обрабатывать навигацию на стороне клиента.
2. Навигация с помощью тегов привязки работает только тогда, когда приложение запущено внутри браузера. Это означает, что мы не можем использовать их в приложениях с использованием Dioxus Desktop.
3. Теги привязки не могут проверить, существует ли целевая страница. Это означает, что мы не можем предотвратить случайные ссылки на несуществующие страницы.

Чтобы решить эти проблемы, маршрутизатор предоставляет нам компонент [`Link`], который мы можем использовать так:

```rust
#[component]
fn NavBar() -> Element {
    rsx! {
        nav {
            Link { to: Route::Home {}, "Home" }
        }
        Outlet::<Route> {}
    }
}
```

`target` в примере выше аналогичен `href` обычного элемента привязки. Однако он сообщает маршрутизатору больше о том, какую навигацию следует выполнить. Он принимает что-то, что может быть преобразовано в [`NavigationTarget`]:

- В примере используется внутренний маршрут. Это наиболее распространённый тип навигации. Он указывает маршрутизатору перейти на страницу внутри нашего приложения, передав вариант перечисления [`Routable`]. Этот тип навигации никогда не может завершиться неудачей, если компонент ссылки используется внутри компонента маршрутизатора.
- [`External`] позволяет нам перейти к URL-адресам за пределами нашего приложения. Это полезно для ссылок на внешние веб-сайты. `NavigationTarget::External` принимает URL-адрес для перехода. Этот тип навигации может завершиться неудачей, если URL-адрес недействителен.

> Компонент [`Link`] принимает несколько свойств, изменяющих его поведение. Подробности см. в документации API.

# Программная навигация

Иногда мы хотим, чтобы наше приложение перешло на другую страницу без того, чтобы пользователь нажимал на ссылку. Это называется программной навигацией.

## Использование навигатора

Мы можем получить навигатор с помощью функции [`navigator`], которая возвращает [`Navigator`].

Мы можем использовать [`Navigator`] для запуска четырёх различных видов навигации:

- `push` выполнит переход к цели. Работает как обычный тег привязки.
- `replace` работает как `push`, за исключением того, что заменяет текущую запись истории вместо добавления новой. Это означает, что предыдущая страница не может быть восстановлена с помощью кнопки «Назад» браузера.
- `Go back` работает как кнопка «Назад» браузера.
- `Go forward` работает как кнопка «Вперёд» браузера.

```rust
#[component]
fn Home() -> Element {
    let nav = navigator();

push
    nav.push(Route::PageNotFound { route: vec![] });

replace
    nav.replace(Route::Home {});

// go back
    nav.go_back();

// go forward
    nav.go_forward();

    rsx! { h1 { "Welcome to the Dioxus Blog!" } }
}
```

Вы, возможно, заметили, что, как и [`Link`], функции `push` и `replace` [`Navigator`] принимают [`NavigationTarget`]. Это означает, что мы можем использовать как `Internal`, так и `External` цели.

## Внешние цели навигации

В отличие от [`Link`], [`Navigator`] не может полагаться на браузер (или веб-представление) для обработки навигации к внешним целям через сгенерированный элемент привязки.

Это означает, что при определённых условиях навигация к внешним целям может завершиться неудачей.

# Провайдеры истории

[`HistoryProvider`] используются маршрутизатором для отслеживания истории навигации и обновления любого внешнего состояния (например, URL браузера).

Маршрутизатор предоставляет два [`HistoryProvider`], но вы также можете создать свой собственный. Две реализации по умолчанию:

- [`MemoryHistory`] — пользовательская реализация, работающая в памяти.
- [`LiveviewHistory`] — пользовательская реализация, работающая с рендерером liveview.
- [`WebHistory`] интегрируется с URL браузера.

По умолчанию маршрутизатор использует [`MemoryHistory`]. Он может быть изменён на использование [`WebHistory`], когда активна функция `web`, но это не гарантировано.

Вы можете переопределить историю по умолчанию:

```rust
#[component]
fn App() -> Element {
    rsx! {
        Router::<Route> { config: || RouterConfig::default() }
    }
}
```

# Callback обновления маршрутизации

В некоторых случаях мы можем захотеть выполнить пользовательский код при изменении текущего маршрута. По этой причине [`RouterConfig`] предоставляет поле `on_update`.

## Как ведёт себя callback?

`on_update` вызывается всякий раз, когда изменяется текущая информация о маршрутизации. Он вызывается после того, как маршрутизатор обновил своё внутреннее состояние, но до обновления зависимых компонентов и хуков.

Если callback возвращает [`NavigationTarget`], маршрутизатор заменит текущее местоположение на указанную цель. Он не вызовет `on_update` снова.

Если в какой-либо момент маршрутизатор столкнётся с ошибкой навигации, он перейдёт в соответствующее состояние, не вызывая `on_update`. Не имеет значения, была ли недействительная цель инициирована при навигации, найдена как цель перенаправления или возвращена самим `on_update`.

## Пример кода

```rust
#[derive(Routable, Clone, PartialEq)]
enum Route {
    #[route("/")]
    Index {},
    #[route("/home")]
    Home {},
}

#[component]
fn Home() -> Element {
    rsx! {
        p { "Home" }
    }
}

#[component]
fn Index() -> Element {
    rsx! {
        p { "Index" }
    }
}

fn app() -> Element {
    rsx! {
        Router::<Route> {
            config: || {
                RouterConfig::default()
                    .on_update(|state| {
                        (state.current() == Route::Index {})
                            .then_some(NavigationTarget::Internal(Route::Home {}))
                    })
            },
        }
    }
}
```

[`NavigationTarget`]: https://docs.rs/dioxus-router/latest/dioxus_router/navigation/enum.NavigationTarget.html
[`RouterConfig`]: https://docs.rs/dioxus-router/latest/dioxus_router/prelude/struct.RouterConfig.html

# Кнопки истории

Некоторые платформы, такие как веб-браузеры, предоставляют пользователям простой способ перемещаться по истории приложения. У них есть элементы интерфейса или интеграция с ОС.

Однако нативные платформы обычно не предоставляют таких удобств, что означает, что приложения, желающие дать пользователям к ним доступ, должны реализовать их самостоятельно. По этой причине маршрутизатор поставляется с двумя компонентами, которые эмулируют кнопки «Назад» и «Вперёд» браузера:

- [`GoBackButton`]
- [`GoForwardButton`]

```rust
fn HistoryNavigation() -> Element {
    rsx! {
        GoBackButton { "Back to the Past" }
        GoForwardButton { "Back to the Future" }
    }
}
```

Как вы, возможно, знаете, браузеры обычно отключают кнопки «Назад» и «Вперёд», если нет истории для навигации. Кнопки истории маршрутизатора тоже пытаются это делать, но в зависимости от [провайдера истории] это может быть невозможно.

Важно отметить, что `WebHistory` не поддерживает эту функцию. Это связано с ограничениями API истории браузера.

Однако в обоих случаях маршрутизатор просто проигнорирует нажатия кнопок, если нет истории для навигации.

Также при использовании `WebHistory` кнопки истории могут
перевести пользователя к записи в истории за пределами вашего приложения.

[`GoForwardButton`]: https://docs.rs/dioxus-router/latest/dioxus_router/components/fn.GoForwardButton.html
