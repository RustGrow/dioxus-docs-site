# Введение

Dioxus — это фреймворк для создания кроссплатформенных приложений на языке программирования Rust. С одной кодовой базой вы можете создавать приложения для веба, десктопа и мобильных платформ.

```rust
use dioxus::prelude::*;

pub fn App() -> Element {
    let mut count = use_signal(|| 0);

    rsx! {
        h1 { "High-Five counter: {count}" }
        button { onclick: move |_| count += 1, "Up high!" }
        button { onclick: move |_| count -= 1, "Down low!" }
    }
}
```

Это руководство разделено на несколько разделов:

- [Туториал](../tutorial/index.md) проведет вас через создание вашего первого приложения на Dioxus.
- [Основные концепции](../essentials/index.md) содержат подробную информацию по темам вроде управления состоянием.
- [Руководства](../guides/index.md) содержат справочную информацию по работе с ассетами, маршрутизацией, тестированием и многому другому.

Сначала пройдите [Туториал](../tutorial/index.md), чтобы познакомиться с Dioxus. Перед началом работы над большим проектом мы настоятельно рекомендуем прочитать все [Основные концепции](../essentials/index.md) и бегло просмотреть [Обзор руководств](../guides/index.md). Это руководство предполагает, что вы уже знаете немного [Rust](https://www.rust-lang.org/)! Если нет, мы рекомендуем прочитать [*the book*](https://doc.rust-lang.org/book/ch01-00-getting-started.html), чтобы сначала изучить Rust.

## Что такое Dioxus?

Dioxus — это удобный для разработчиков фреймворк, который позволяет создавать кроссплатформенные приложения с одной кодовой базой. Вы пишете приложения на Rust, стилизуете их с помощью HTML/CSS, расширяете возможности нативными API и распространяете их как нативные пакеты для каждой платформы.

![Диаграмма архитектуры мультиплатформенного приложения](/assets/static/dioxus-architecture-diagram.png)

Во многих отношениях Dioxus похож на Flutter: мы интегрируем собственные инструменты сборки, развиваем экосистему и предоставляем GUI-фреймворк. В ключевых областях Dioxus использует другой подход:

- Приложения объявляются с помощью HTML и CSS вместо кастомного решения для стилизации
- Реактивность вдохновлена веб-фреймворками вроде React и SolidJS
- Код Dioxus выполняется нативно без виртуальной машины, обеспечивая вызовы системных API без накладных расходов

Наша цель — создать «Flutter, но лучше»: быстрее, легче и ориентированный на веб. Вы можете думать о Dioxus как о гибриде [Flutter](http://flutter.dev), [React Native](http://reactnative.dev) и [NextJS](http://nextjs.org): кроссплатформенные приложения с отличной поддержкой фулстека. Сегодня приложения Dioxus можно писать только на Rust, но в будущем мы планируем поддерживать и другие языки.

## Почему Dioxus?

Мы создали Dioxus, потому что считаем, что текущий стандарт разработки приложений слишком сложен. Разработчикам нужно изучать и устанавливать десятки различных инструментов, чтобы просто запустить свое приложение. Нам нужен более простой и мощный фреймворк, чтобы воплощать идеи в реальность.

![Стек приложения](/assets/static/dioxus-app-stack.png)

Наше видение Dioxus — это фреймворк, который быстр, гибок и имеет минимальную кривую обучения. Мы хотим, чтобы разработчики уверенно запускали свои приложения от идеи до продакшена как можно быстрее. Мы верим, что меньше инструментов и более простая архитектура упрощают разработку приложений. Приложения, которые проще создавать, выходят быстрее и с большей вероятностью достигают успеха.

## Превосходный опыт разработчика

В Dioxus мы стремимся поддерживать очень высокую планку для опыта разработчика. Мы считаем, что создание приложений должно быть веселым и простым. Мы работаем над развитием самого Rust, разрабатывая технологии вроде [Subsecond](https://crates.io/crates/subsecond) — горячей перезагрузки Rust, [WASM bundle-splitting](https://crates.io/crates/wasm-splitter), [linker-based asset bundling](https://crates.io/crates/manganis) и модульного [WGPU-based HTML/CSS renderer](https://crates.io/crates/blitz).

## Синтаксис и экосистема

Синтаксис Dioxus похож на JSX разметку React, заимствуя подход React к компонентам и хукам. Все компоненты — это функции Rust, которые принимают `Properties`, определяют состояние с помощью хуков и возвращают `Element`. Мы поддерживаем только разметку, объявленную с помощью макроса `rsx! {}`; это гарантирует, что ваше приложение автоматически оптимизировано и поддерживает наши мощные инструменты разработки.

```rust
#[component]
fn Component(name: String) -> Element {
    let mut count = use_signal(|| 0);

    rsx! {
        em { "Привет, {name}" }
        p { "Счетчик: {count}" }
    }
}
```

Dioxus разработан так, чтобы его было легко расширять, и он достаточно тонок над системными API. Это означает, что вы можете легко обращаться к системным API, когда встроенных API недостаточно. При таргетировании на веб это может означать использование [`web-sys`](http://crates.io/crates/web-sys/), на Android — [`jni`](http://crates.io/crates/jni), а на iOS — [`objc2`](https://crates.io/crates/objc2).

```rust
fn PromptModal() {
    #[cfg(web)]
    web_sys::call_web_function();

    #[cfg(android)]
    jni_sys::call_android_function();

    #[cfg(ios)]
    objc2::call_ios_function();
}
```

Основной фреймворк Dioxus охватывает ряд утилит, которые либо сложно спроектировать, либо должны поддерживать наши инструменты разработки:

- [Маршрутизация приложений](../essentials/router/index.md)
- [Интеграция с бэкендом через серверные функции](../essentials/fullstack/index.md)
- [Включение и оптимизация](../essentials/ui/assets.md) ассетов
- [Управление состоянием](../essentials/basics/index.md) (реактивность на основе сигналов)
- [SDK](http://github.com/dioxusLabs/sdk): интеграции с системой от первого лица

## Кто финансирует Dioxus?

Dioxus финансируется за счет корпоративного спонсорства, корпоративных контрактов на поддержку, [краудфандинга](https://github.com/sponsors/DioxusLabs#sponsors) и [венчурного капитала](http://ycombinator.com/companies/dioxus-labs). Мы стремимся поддерживать здоровый баланс финансирования, чтобы уравновесить различные конкурирующие видения будущего. Мы хотим предоставить «Flutter, но лучше» для всех — не контролируемый Apple, Meta или Google — и нам нужно обеспечить устойчивое долгосрочное финансовое будущее Dioxus.

В конечном итоге мы хотели бы, чтобы Dioxus был самодостаточным. Это означает, что у вас eventually будет возможность развертывать свои production-приложения с помощью [Dioxus Deploy](https://dioxuslabs.com/deploy). Доход от *Dioxus Deploy* в свою очередь будет финансировать разработку самого Dioxus.

Мы стремимся сохранить Dioxus бесплатным и с открытым исходным кодом навсегда. Вам никогда не придется платить нам за создание приложений, и мы никогда не изменим лицензию Dioxus.
