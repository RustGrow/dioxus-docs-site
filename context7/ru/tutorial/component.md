# Ваш первый компонент

Теперь, когда мы инициализировали наше приложение *HotDog*, мы можем начать создавать его компоненты.

## Что такое компонент?

В Dioxus приложения состоят из отдельных функций, называемых *Компонентами*, которые принимают некоторые *Свойства* и рендерят *Элемент*:

```rust
fn DogApp(props: DogAppProps) -> Element {
        todo!()
    }
```

## Свойства компонента

Все компоненты принимают объект, который описывает, какие параметры может принимать компонент. Все структуры `Props` в Dioxus должны реализовывать трейт `Properties`, который требует и `Clone`, и `PartialEq`:

```rust
#[derive(Props, PartialEq, Clone)]
    struct DogAppProps {
        breed: String,
    }
```

Dioxus предоставляет макрос `#[component]` для упрощения определения компонентов. Этот макрос преобразует параметры аннотированной функции в скрытую сопутствующую структуру.

```rust
#[component]
    fn DogApp(breed: String) -> Element {
        todo!()
    }
```

При создании приложений вы будете часто использовать макрос `#[component]`. При создании библиотек мы обычно рекомендуем использовать derive Props.

## Свойства неизменяемы

Если вы знакомы с JavaScript, то вы также можете быть знакомы с библиотеками вроде [React](http://react.dev). Dioxus *очень* похож на React: если вы знаете React, то вам будет комфортно с Dioxus.

Как и в React, компоненты Dioxus рендерятся путем вызова функции компонента. При каждом рендере Dioxus делает `.clone()` свойств компонента. Это гарантирует, что вы не сможете случайно изменить свои свойства, что может привести к трудноотслеживаемым проблемам с управлением состоянием.

```rust
#[component]
    fn DogApp(breed: String) -> Element {
        tracing::info!("Rendered with breed: {breed}");

        todo!()
    }
```

Dioxus предоставляет типы, которые делают вызов `.clone()` дешевле, так что не беспокойтесь о проблемах с производительностью.

## Функции компонентов вызываются несколько раз

Как и в React, Dioxus будет вызывать вашу функцию компонента несколько раз в течение его жизненного цикла. Это называется *перерисовкой*. В Dioxus перерисовки очень дешевы (намного дешевле, чем в React!). В большинстве случаев вам не стоит слишком беспокоиться о слишком частых перерисовках.

Когда Dioxus перерисовывает ваш компонент, он сравнивает `Element` из последнего рендера с `Element` из текущего рендера.

Например, когда свойство `breed` меняется на компоненте DogApp, Dioxus вызовет функцию DogApp второй раз и сравнит предыдущий Element с новым Element.

```rust
#[component]
    fn DogApp(breed: String) -> Element {
        rsx! {
            "Breed: {breed}"
        }
    }
```

![Diffing](/assets/06_docs/diffing_diagram.png)

Dioxus будет перерисовывать ваш компонент только в двух случаях:

- Когда `Props` меняются, как определено `PartialEq`
- Когда функция вроде `signal.set()` или `signal.write()` вызывает `Scope.needs_update()`

В отличие от React, все компоненты Dioxus *мемоизированы по умолчанию*, что означает, что Dioxus всегда будет сравнивать `Props` перед решением о перерисовке вашего компонента. В качестве дополнительной оптимизации Dioxus сравнивает только динамические части вашего RSX. Элементы, которые не содержат динамических данных, не будут проверяться на изменения.

## Композиция компонентов

В Dioxus *Компоненты* компонуются вместе для создания *Приложений*. Каждый компонент будет хранить свое собственное состояние и обрабатывать свои собственные обновления. Это упрощает абстрагирование вашего приложения на разные части и даже делится частями вашего приложения в виде библиотек для использования другими.

Чтобы компоновать компоненты вместе, мы будем использовать макрос `rsx! {}` для определения структуры нашего приложения.

```rust
#[component]
    fn App() -> Element {
        rsx! {
            Header {}
            DogApp { breed: "corgi" }
            Footer {}
        }
    }
```

Мы подробнее рассмотрим `rsx! {}` в [следующей главе](rsx.md).
