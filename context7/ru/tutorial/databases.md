# Работа с базами данных

Наше приложение HotDog собирается отлично! Мы реализовали очень простой бэкенд, который сохраняет избранные изображения собак пользователя в локальный файл "dogs.txt".

На практике вы, вероятно, захотите хранить данные в полноценной базе данных. Современные базы данных *намного* мощнее текстового файла!

Если вы уже хорошо разбираетесь в базах данных, перейдите сразу к [разделу, где мы интегрируем Sqlite с HotDog](#добавление-операций-базы-данных-в-hotdog).

## Выбор базы данных

В современную эпоху разработки приложений есть *множество* баз данных на выбор, каждая со своими сильными сторонами, слабостями и компромиссами. Для приложений с несколькими пользователями вполне подойдет «более простая" база данных, которую легче управлять. Для приложений с множеством пользователей вы можете рассмотреть более продвинутые базы данных с дополнительными инструментами для удовлетворения более строгих требований.

Вот (неполный!) список баз данных и краткое резюме каждой:

- [PostgreSQL](https://www.postgresql.org): Продвинутая база данных, известная своей мощной системой плагинов.
- [MySQL](https://www.mysql.com): Самая популярная в мире база данных с открытым исходным кодом, подходящая для всех приложений.
- [SQLite](https://www.sqlite.org): Простой файл-движок, известный своей надежностью и встраиваемостью.
- [Oracle](https://www.oracle.com/database/): Продвинутая коммерческая база данных, известная своими enterprise-функциями.
- [Redis](http://redis.io): Простая key-value база данных, известная своей высокой производительностью.
- [MongoDB](https://www.mongodb.com/): База данных, идеальная для данных, которые не вписываются в строки и столбцы.
- [SurrealDB](https://surrealdb.com/): Новая «всё-в-одном" база данных, которая объединяет множество моделей.
- [CockroachDB](https://www.cockroachlabs.com): Распределенная SQL-база данных, разработанная для высокой доступности.
- [и многие другие](https://dev.to/shreyvijayvargiya/list-of-45-databases-in-the-world-57e8)!

Есть много разных типов баз данных, каждая хороша в разных задачах. К ним могут относиться:
- **Реляционные**: традиционный подход со строками/столбцами/таблицами.
- **Документные**: хранение неструктурированных или слабо структурированных данных.
- **Временные ряды**: хранение и запрос большого количества данных, изменяющихся со временем.
- **Графовые**: запрос данных на основе их связей с другими данными.
- **Key-value**: хранение только пар ключ-значение — быстрая concurrent HashMap.
- **In-memory**: разработаны для операций с низкой задержкой, обычно используются как кэш.
- **Встраиваемые**: база данных, которая поставляется *внутри* вашего приложения.

Для большинства приложений — если у вас нет специфических требований — мы рекомендуем мейнстрим реляционную базу данных вроде PostgreSQL или MySQL.

> 📣 PostgreSQL в настоящее время является очень интересным вариантом: ее можно расширить для поддержки временных рядов, векторов, графов, поиска и геопространственных данных с помощью плагинов.

В некоторых случаях вы можете захотеть базу данных, которая специфична для *только одного экземпляра приложения* или *машины пользователя*. В этих случаях вы захотите использовать встраиваемую базу данных вроде [SQLite](https://www.sqlite.org) или [RocksDB](https://rocksdb.org).

## Добавление операций базы данных в HotDog

Для *HotDog* мы будем использовать Sqlite. *HotDog* — очень простое приложение, и у него будет только один пользователь: вы!

Чтобы добавить функциональность sqlite в *HotDog*, мы подключим крейт `rusqlite`. Обратите внимание, что `rusqlite` предназначен только для компиляции на сервере, поэтому мы поместим его за feature gate `"server"` в нашем Cargo.toml.

```toml
[dependencies]
# ....
rusqlite = { version = "0.32.1", optional = true } # <--- добавьте rusqlite

[features]
# ....
server = ["dioxus/server", "dep:rusqlite"] # <---- добавьте dep:rusqlite
```

Для подключения к нашей базе данных мы будем использовать `rusqlite::Connection`. Соединения Rusqlite не являются потокобезопасными и должны существовать один-на-поток, поэтому нам нужно будет обернуть их в thread_local.

```rust
// The database is only available to server code
#[cfg(feature = "server")]
thread_local! {
    pub static DB: rusqlite::Connection = {
        // Open the database from the persisted "hotdog.db" file
        let conn = rusqlite::Connection::open("hotdog.db").expect("Failed to open database");

        // Create the "dogs" table if it doesn't already exist
        conn.execute_batch(
            "CREATE TABLE IF NOT EXISTS dogs (
                id INTEGER PRIMARY KEY,
                // url TEXT NOT NULL
            );",
        ).unwrap();

        // Return the connection
        conn
    };
}
```

## Создание таблицы

Давайте создадим таблицу для хранения наших избранных собак:

```rust
// The database is only available to server code
#[cfg(feature = "server")]
thread_local! {
    pub static DB: rusqlite::Connection = {
        // Open the database from the persisted "hotdog.db" file
        let conn = rusqlite::Connection::open("hotdog.db").expect("Failed to open database");

        // Create the "dogs" table if it doesn't already exist
        conn.execute_batch(
            "CREATE TABLE IF NOT EXISTS dogs (
                id INTEGER PRIMARY KEY,
                // url TEXT NOT NULL
            );",
        ).unwrap();

        // Return the connection
        conn
    };
}
```

## Сохранение и получение данных

Теперь мы можем обновить наши серверные функции для использования базы данных вместо текстового файла:

```rust
#[server]
async fn save_dog(image: String) -> Result<()> {
    DB.with(|f| f.execute("INSERT INTO dogs (url) VALUES (?1)", &[&image]))?;
    Ok(())
}
```
