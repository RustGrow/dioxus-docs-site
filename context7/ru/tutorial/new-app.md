# Создание нового проекта

Вы можете создать новый проект Dioxus, запустив следующую команду и следуя подсказкам:

```sh
dx new hot_dog
```

<video src="/assets/06_docs/dx_new_06.mp4" controls></video>

Вам нужно будет выбрать шаблон для начала работы.

- Bare-bones: очень простая настройка с только `main.rs` и папкой `assets`.
- Jumpstart: собранное приложение с компонентами, представлениями и предложенной структурой.
- Workspace: полная настройка cargo workspace с разными крейтами для каждой платформы.

Мы будем использовать шаблон bare-bones для *HotDog*, так как наше приложение будет довольно простым.

- Выберите "false", когда спросят, хотите ли вы создать фулстек-сайт.
- Выберите "false" для роутера, хотя мы *в итоге* добавим роутер в приложение.
- Выберите "true" для TailwindCSS.
- Выберите "false" для промптов для LLM.
- Выберите "Web" как платформу по умолчанию.

> 📣 Вам не нужен `dx new` для создания новых приложений Dioxus! Приложения Dioxus — это проекты Rust, и их также можно собирать с помощью инструментов вроде cargo.

## Запуск проекта

После генерации проекта вы можете запустить его следующей командой:

```sh
cd hot_dog
dx serve
```

<video src="/assets/06_docs/dx_serve_06.mp4" controls></video>

Это запустит сборку cargo и запустит веб-сервер для обслуживания вашего приложения. Если вы посетите адрес "serve" (в данном случае, `http://127.0.0.1:8080`), то вы увидите экран загрузки в вашем браузере:

![loading](/assets/06_docs/hotdog_loading.png)

Как только приложение загрузится, вы должны увидеть стартовое приложение Dioxus по умолчанию:

![app](/assets/06_docs/default_dioxus_app.png)

Поздравляем! У вас есть ваше первое приложение Dioxus.

## Структура приложения

Откройте приложение в редакторе и посмотрите на его структуру:

```sh
├── Cargo.lock
├── Cargo.toml
├── Dioxus.toml
├── README.md
├── assets
│   ├── favicon.ico
│   ├── header.svg
│   └── main.css
└── src
    └── main.rs
```

Все приложения Rust состоят из корневого `Cargo.toml` с файлом `main.rs`, расположенным в папке `src`. Наш CLI `dx` предварительно заполнил эти файлы зависимостью `dioxus` и стартовым кодом, чтобы мы могли быстро начать разработку.

Ассеты в Dioxus можно размещать где угодно в проекте, но мы рекомендуем оставлять их в папке `assets`.

### The Cargo.toml

`Cargo.toml` описывает зависимости нашего приложения и указывает настройки компилятора. Все приложения Rust *компилируются*: мы запускаем Rust-инструмент `cargo`, который собирает наши `.rs` файлы вместе и генерирует финальный бинарный исполняемый файл (вроде `.exe`), который запускает наше приложение.

Все приложения Dioxus будут включать `dioxus` как зависимость:

```toml
[dependencies]
dioxus = { version = "0.7.0" }
```

Предварительно собранные шаблоны Dioxus инициализируют различные cargo features для вашего приложения. `dx` будет использовать их, чтобы решить, какие cargo features включать, когда вы указываете флаги `--web` или `--desktop`. Например, если вы используете `dx serve --desktop` для сборки вашего приложения для десктопа, `dx` вызовет `cargo build --no-default-features --features desktop`.

```toml
[features]
default = ["web"]
web = ["dioxus/web"]
desktop = ["dioxus/desktop"]
mobile = ["dioxus/mobile"]
```

### Dioxus.toml

Файл `Dioxus.toml` содержит специфичную для Dioxus конфигурацию для бандлинга и развертывания вашего приложения. Нам пока не нужно конфигурировать `Dioxus.toml` для нашего приложения.

### Папка Assets

Чтобы включить ассеты в ваше приложение Dioxus, вы захотите использовать макрос `asset!()`, который мы рассмотрим позже в главе [Стили и ассеты](assets.md). Вы можете включать ассеты из любого места в файловом дереве вашего приложения, но мы рекомендуем использовать предварительно сгенерированную папку `assets`.

### tailwind.css

Dioxus имеет встроенную поддержку TailwindCSS! При обслуживании и сборке вашего приложения `dx` автоматически запускает TailwindCSS CLI, если обнаруживает `tailwind.css` в корне вашего приложения. Вывод tailwind-компилятора по умолчанию находится в папке assets.

### main.rs

Наконец, `main.rs`. Файл `main.rs` — это точка входа нашего приложения, содержащая функцию `fn main`. Все Rust-исполняемые файлы начинают свою жизнь в `main`.

`main` нашего приложения HotDog выглядит так:

```rust
use dioxus::prelude::*;

    fn main() {
        dioxus::launch(App);
    }
```

Функция `launch` вызывает платформенно-специфичную функцию `launch` в зависимости от того, какой feature (web/desktop/mobile) включен в `dioxus`. `launch` принимает корневой компонент, обычно называемый `App`.

Мы подробнее рассмотрим компоненты в [следующей главе](component.md).

## Возвращение к основам

Шаблон bare-bones предоставляет базовый стартовый код для нашего приложения. Однако мы хотим начать *действительно* с нуля, поэтому удалим компонент `Hero` и очистим компонент `App` до основ:

```rust
use dioxus::prelude::*;

    fn main() {
        dioxus::launch(App);
    }

    #[component]
    fn App() -> Element {
        rsx! { "HotDog!" }
    }
```
