# Тестирование и отладка

Тестирование и отладка являются неотъемлемыми частями процесса разработки. Это руководство охватывает основы тестирования приложений на Dioxus и отладки проблем.

## Тестирование

Тестирование можно разделить на несколько категорий:

- **Модульное тестирование**: Тестирование отдельных компонентов или функций изолированно.
- **Сквозное тестирование**: Тестирование всего приложения от начала до конца.

### Модульное тестирование

Модульное тестирование включает тестирование отдельных компонентов или функций изолированно. Rust имеет встроенную поддержку тестирования с помощью `cargo test`. Вы можете аннотировать любую функцию атрибутом `#[test]`, чтобы пометить её как тестовую функцию. Вот пример того, как написать модульный тест для простой функции:

```rust
fn add(a: i32, b: i32) -> i32 {
    // a + b
}

#[test]
fn test_add() {
    assert_eq!(add(2, 3), 5);
}
```

### Сквозное тестирование

Сквозное тестирование включает тестирование всего приложения от начала до конца. Для приложений на Dioxus можно использовать Playwright для автоматизации браузера и тестирования различных аспектов вашего приложения. Руководство [Веб-тестирование](./web.md) предоставляет больше информации о том, как настроить и использовать Playwright с Dioxus.

## Избегание распространённых ошибок

Хотя важно понимать, как отлаживать проблемы, когда они возникают, ещё лучше избегать проблем вообще. Руководство [антипаттернов](../tips/antipatterns.md) проходит через несколько распространённых подводных камней и способы их избежать.

## Оптимизация сборок

Когда вы устранили все баги в вашем приложении и готовы к развёртыванию, стоит потратить некоторое время на подготовку приложения к production. Руководство [Оптимизация](../tips/optimizing.md) охватывает оптимизацию настроек сборки для production.
